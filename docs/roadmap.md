# ロードマップと残作業

## 1. 現状

- 写真索引、一覧、詳細、検索、圧縮、取り込み、ログ監視、XMP、トレイ、自動起動、Linuxパッケージ、systemdユーザーサービス（deb/pacman、任意）まで実装済み。
- 失敗理由の表示と再試行（圧縮・取り込み・デーモン処理）、UI/デーモンのログファイル出力とログフォルダを開く導線まで実装済み。
- LinuxのCI/Releaseは成功。deb / AppImage / pacmanの生成を確認済み。
- Windows実機、AppImage実起動、deb/pacmanインストール後起動は未検証。
- 一覧・検索は全件の仮想グリッド＋年レールで表示する。100k合成DB（`photo_context` 5万行を含む）で索引61.5 ms、ページ0.72 ms、warm初回フレーム179–187 ms、cold-ish 226–235 ms（空DB 158–163 ms）を計測済み。真のOS cold起動（ページキャッシュ破棄後）は未測定。

## 3. 明示的な非目標

- VRChatアカウントログインを必須にする。
- クラウド同期を既定で有効にする。
- 写真の完全削除を既定にする。
- 公式WebSocket（pipeline）で写真の文脈を取る（取得できない）。
- 画像編集（トリミング、色補正、合成）。
- 顔認識、AI自動タグ付け。

## 4. 未決の判断項目

以下は次回以降にユーザーへ確認する。

1. Windows配布はNSISで確定（v0.1.1）。ポータブルZIPも必要か。
2. deb/pacmanのsystemdユーザーサービスは任意提供で確定（ADR-0010）。既定はアプリ管理の自動起動を継続し、サービス利用時はUIの自動起動をOFFにする運用とする。
3. 真のOS cold起動（ページキャッシュ破棄後）で1 s目標をどう確定するか。cold-ishは226–235 msで予算内、起動時の索引クエリは1回に統合済み。
4. UIとデーモンのIPCを導入するか、SQLite共有を続けるか。
5. 英語UIをいつ入れるか。
6. AppImageの自動起動をデスクトップ環境ごとに検証する範囲。

## 5. リリース判定

β公開の条件:

- CIとReleaseが緑。
- Linuxの3形式が生成できる。
- 主要な写真索引・紐付け・圧縮の手動確認が通る。
- 既知の制約がREADMEとHANDOFFに書かれている。
- クラッシュやデータ消失につながる未解決バグがない。

正式版の条件:

- Windows実機検証済み。
- 10万枚の性能目標（warm 179–187 ms、cold-ish 226–235 ms）を満たし、真のOS cold起動でも1 s目標を満たす。
- バックアップ/復元手順が文書化されている。
- パッケージのインストール/アンインストールが確認済み。

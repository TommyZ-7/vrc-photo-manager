# English UI (i18n) — design

Issue: #19

## Intent

`AppSettings.language` is persisted but unused. Every user-facing string in
`crates/ui` is a Japanese literal, so selecting another language does nothing.
This change introduces a shared translation catalog and makes the whole UI
language-aware, with Japanese and English as the first two languages.

The implementation must make a third language a data change, not a code
change: dropping a new locale file into the catalog directory should make it
appear in Settings and work through the existing fallback.

## Goals

- All user-facing UI strings in `crates/ui` come from translation keys:
  navigation, screens, dialogs, toasts, notifications, update view, input
  placeholders, empty states, and validation/error text.
- The daemon tray menu and tooltip use the same catalog.
- Settings has a language selector that applies immediately and persists to
  `AppSettings.language`; the selection survives restart.
- Japanese remains the default. A missing translation falls back to Japanese,
  never to a raw key such as `photos.empty`.
- Adding a language means adding `crates/i18n/locales/<code>.yml` with a
  native name and translated keys. No Rust enum, match arm, or settings
  migration is required.
- Existing behavior, layout, and visual design are unchanged in Japanese.

## Non-goals

- Translating core error strings, compression job error details, log
  messages, or arbitrary `ScanFailure.message` text. They are technical detail
  text shown as-is. Known daemon error summaries are localized (section 6).
- Rewriting historical `daemon_errors` rows on a language switch. Rows store
  the key and arguments, so the UI renders them in the current language
  without rewriting the database.
- Translating user data (photo tags, notes, world names, profile names, demo
  data, file paths).
- RTL layout, OS-locale auto-detection, or a "follow system" option.
- Translating `gpui-component`'s built-in widget labels. Its bundled catalogs
  have no Japanese, so it already falls back to English; this change does not
  make that worse.
- Changing date/time storage, sorting, or number semantics. Only display
  strings are localized.

## Anti-goals

- A half-translated English UI where toasts, update view, or the tray remain
  Japanese.
- A language switch that requires an app restart or resets unrelated settings.
- A raw translation key visible anywhere, including for a future language
  that is only partially translated.
- Hardcoding `if language == "en"` branches in screens.
- Breaking Japanese text, line wrapping, or the existing settings layout.

## Current state

- `crates/core/src/settings.rs` stores `language: String`, default `"ja"`.
  The value is saved in the settings JSON but never read by the UI.
- `crates/ui/src/main.rs` has no locale initialization.
- `crates/ui/src/app.rs` builds `InputState` placeholders with Japanese
  literals. `Screen::title` and all screen modules use Japanese literals.
- `crates/ui/src/ui/settings.rs` shows a footer line `言語: {language}`, but
  there is no selector.
- `crates/ui` contains about 860 Japanese string literals (about 650 unique).
  Roughly 600 are user-facing; the rest are tests, logs, demo data, and
  technical messages.
- `gpui-component` (reached through `gpui-kit 0.8.1`) already depends on
  `rust-i18n 4.2` and owns a global locale. Calling `rust_i18n::set_locale`
  also affects its built-in labels.
- Date display is numeric (`%m/%d %H:%M`, `%Y/%m/%d %H:%M`) except the year
  rail's `2025年4月`. Number formatting uses comma thousands and `k` suffixes;
  both are acceptable in Japanese and English.
- The daemon reloads `AppSettings` every 500 ms and owns the tray menu.

## Approaches considered

| Approach | What it does | Trade-off |
| --- | --- | --- |
| **A. Shared `vrc-photon-i18n` crate + rust-i18n (chosen)** | One catalog crate used by UI and daemon. `rust-i18n` embeds YAML at compile time; a small wrapper owns fallback and locale discovery. | One source of truth, language addition is one YAML file, daemon tray can share it. Adds one workspace crate and a wrapper API. |
| B. Catalog inside `crates/ui` only | Put `rust-i18n` in the UI crate and translate major screens. | Smaller diff, but the tray and shared code cannot use it, and the issue's "major screens" leaves visible Japanese in toasts/update view. Rejected. |
| C. Hand-written enum/static map | `Language` enum with `match` arms per string. | Type-safe and dependency-free, but every new language edits every match. Contradicts the extensibility requirement. Rejected. |

A was chosen because the request explicitly asks for future languages and the
tray is a user-facing surface that should not drift from the UI.

## Design

### 1. Crate layout

New workspace member `crates/i18n`:

```text
crates/i18n/
  Cargo.toml            # package vrc-photon-i18n
  locales/
    ja.yml              # source of truth
    en.yml
  src/lib.rs            # locale discovery, lookup, fallback, tr!/tr_args!
  tests/catalog.rs      # completeness and no-raw-key tests
  tests/source_keys.rs  # every tr!("...") literal exists in ja.yml
```

`crates/ui` and `crates/daemon` depend on `vrc-photon-i18n` by path. The
workspace `Cargo.toml` gains `rust-i18n = "4.2"` and the new member.

`crates/i18n/src/lib.rs` calls:

```rust
rust_i18n::i18n!("locales", fallback = "ja");
```

The wrapper does not rely on `t!` for fallback. It reads the generated
`_rust_i18n_backend()` directly so it can implement exact → base-language →
Japanese fallback and guarantee that a missing key never reaches the UI.

### 2. Catalog format

Use `_version: 1` split locale files with flat, dot-separated keys:

```yaml
_version: 1
language.name: "日本語"
nav.photos: "写真"
photos.empty: "写真がありません。..."
photos.selected: "%{count} 件選択中"
```

Rules:

- Keys are semantic and lowercase: `<surface>.<element>[.<variant>]`.
  Namespaces: `common`, `language`, `nav`, `titlebar`, `sidebar`, `photos`,
  `gallery`, `search`, `compression`, `dashboard`, `settings`, `notifications`,
  `import`, `viewer`, `update`, `dialog`, `tray`, `date`, `errors`.
- Placeholders use `%{name}` and are passed through `tr_args!`.
- Date templates (`date.captured_month`, `date.unknown`) are keys, not
  `if locale ==` branches, so a third locale can change the order and wording.
- Count messages are phrased so they read correctly for 1 and many:
  `"Selected: %{count}"`, `"Photos: %{count}"`, `"Moved %{count} to the
  trash"`. No plural machinery is required for ja/en. If a future language
  needs plural categories, the catalog can add `.one`/`.other` keys and the
  wrapper can grow a plural rule; that is a localized extension, not a
  rewrite.
- Japanese is the source of truth. Every key in `ja.yml` must exist in
  `en.yml` (tested), so English is complete rather than silently falling
  back. Other languages may be partial; missing keys fall back to Japanese.
- `language.name` is mandatory in every locale file and is the label shown in
  the Settings selector. A locale without it still appears, labeled with its
  code, so a partially prepared file cannot break the screen.

### 3. Public API

```rust
pub const DEFAULT_LOCALE: &str = "ja";
pub const MISSING: &str = "—";

pub struct LocaleInfo {
    pub code: String,
    pub name: String, // native name, e.g. "日本語" / "English"
}

pub fn normalize(code: &str) -> String;        // unknown/empty -> "ja"
pub fn set_locale(code: &str) -> String;       // normalize + rust_i18n::set_locale
pub fn current_locale() -> String;
pub fn locales() -> Vec<LocaleInfo>;           // discovered from catalogs, ja first
pub fn tr(key: &str) -> String;                // current locale
pub fn tr_in(locale: &str, key: &str) -> String;
pub fn tr_args(key: &str, args: &[(&str, String)]) -> String;
pub fn tr_args_in(locale: &str, key: &str, args: &[(&str, String)]) -> String;

#[macro_export]
macro_rules! tr { ... }       // tr!("nav.photos")
#[macro_export]
macro_rules! tr_args { ... }  // tr_args!("photos.selected", count = count)
```

Lookup order for `tr_in(locale, key)`:

1. exact locale (`en`, `ja`)
2. base language for a regional code (`pt-BR` → `pt`)
3. Japanese
4. `MISSING` (`"—"`), with a `tracing::warn!` that names the key and locale

The wrapper calls `rust_i18n::replace_patterns` after lookup. `tr_args!`
converts each value to `String`; `%{count}` and friends are replaced. A
placeholder missing from a translation stays visible as `%{name}`; the
catalog test checks that no catalog value contains a placeholder not passed by
its call site where the call site is statically known.

`set_locale` also calls `rust_i18n::set_locale`, so `gpui-component` widgets
follow the same global locale.

### 4. Delivery

The migration ships as one PR and one release. The language selector is added
early so the switch can be exercised while the remaining files are migrated,
but the branch is not merged until every surface in section 9 is keyed and the
manual QA passes. There is no feature flag and no intermediate release with a
live selector and a half-translated English UI.

### 5. Persistence and runtime switch

`AppSettings.language` stays a `String`; no serde migration is needed. This is
deliberate: a new locale file is enough to make a new code valid, and unknown
codes normalize to `"ja"`.

Startup:

- `App::new` loads `AppSettings`, calls `vrc_photon_i18n::set_locale(&settings.language)`
  before creating input states and before `reload_all`.
- `main.rs` does not need a separate call.
- The daemon loads settings at startup and calls `set_locale` before building
  the tray.

Settings change:

- `App::set_language(code, cx)`:
  1. normalize and ignore a no-op;
  2. set `settings.language`, save; on failure restore the previous value and
     show a translated error toast;
  3. call `vrc_photon_i18n::set_locale`;
  4. update every `InputState`/`TextareaState` placeholder through
     `set_placeholder`;
  5. clear cached rendered text: `PhotoBrowser::labels` for both grids (the
     year rail's shaped month labels);
  6. `cx.notify()`.

`GalleryView` observes `App`, so it re-renders on the same notification.
`ViewerMorphView` contains no text. Transient toasts already in flight keep the
language they were created in; new toasts use the new language. The
notification modal recomputes its labels from state on every render.
`ImportSource::summary`, `ImportDialogOrigin::run_summary`, scan progress, and
the sidebar status card are already formatted during render and need no cache
invalidation. `UpdateNotice` changes from a preformatted `message: String` to
`{ kind, version, reason }` so its text is built at render time; the startup
toast built from it is transient and keeps the language it was created in.

The daemon's 500 ms settings reload compares `settings.language` with the
in-memory value. On change it calls `set_locale` and `Tray::set_language`, so
the tray follows a UI switch without a daemon restart. `Tray::set_language`
updates the open/pause/quit menu labels and re-renders the status line.

### 6. Daemon error localization

`daemon_errors` gains two nullable columns through schema v10:

```sql
ALTER TABLE daemon_errors ADD COLUMN message_key TEXT;
ALTER TABLE daemon_errors ADD COLUMN message_args TEXT;
```

- `message_key` is a catalog key such as `daemon.scan_failed`.
- `message_args` is a JSON object of string values, e.g.
  `{"count":"3"}` or `{"path":"/photos"}`.
- `message` remains the human-readable fallback. New rows write it in the
  locale active at write time so an older UI or a direct SQLite reader still
  sees a useful sentence. Existing rows keep `message` and have NULL key/args.

`DaemonError` gains `message_key: Option<String>` and
`message_args: Option<String>`. `Db::record_daemon_error_i18n` writes all
three fields; the existing `record_daemon_error` delegates with NULL key/args.
The v10 migration follows the existing immediate-transaction pattern and is
safe to retry after a crash between the DDL and `user_version`.

The daemon's user-facing summaries use a small `LocalizedError` value:

```rust
struct LocalizedError {
    key: &'static str,
    args: Vec<(&'static str, String)>,
}
```

`report_localized_error` renders `message` with `tr_args`, serializes `args`
to JSON, and calls `record_daemon_error_i18n`. Technical errors that have no
catalog key keep using `record_daemon_error`.

The UI renders `message_key` + `message_args` in the current locale, falling
back to `message` when the key is unknown, the JSON is invalid, or the
translation is missing. This means a stored error written in Japanese becomes
English as soon as the user switches, without a database rewrite. It also
means old rows from before v10 continue to show their original sentence.

### 7. Settings UI

Add a `language_card` near the top of the Settings column, before the theme
card:

- Title: `settings.language.title` ("言語" / "Language").
- Hint: `settings.language.hint` ("変更はすぐに反映されます" / "Changes apply
  immediately.").
- A wrapping row of chips, one per `locales()`, styled like the existing FPS
  preset chips. Each chip shows `LocaleInfo::name`; the active chip uses the
  accent fill. ID: `language-{code}`.
- Clicking calls `App::set_language`.

The existing footer line becomes a translated summary:
`settings.footer.summary` with `language` and `cache` placeholders, or two
separate translated fragments. The raw `self.settings.language` code is not
shown.

The selector is data-driven. A future `de.yml` with `language.name: "Deutsch"`
appears automatically; no UI code changes.

### 8. Date and number display

- `format_captured_month` in `crates/ui/src/state/year_rail.rs` becomes
  `format_captured_month_in(locale, month)`; the current-locale wrapper keeps
  the call sites simple.
  - `date.captured_month` is a catalog template with `%{year}`, `%{month}`,
    and `%{month_name}`. ja uses `%{year}年%{month}月`; en uses
    `%{month_name} %{year}`. A third locale overrides the same key, so the
    data-only goal also holds for dates.
  - `date.unknown` is the unknown-month label (`不明` / `Unknown`).
  - `date.month_name.1` … `date.month_name.12` live in both catalogs.
- Numeric timestamps (`%m/%d %H:%M`, `%Y/%m/%d %H:%M`) stay numeric in both
  languages. They are unambiguous and already used in tooltips/status lines.
- `format_count` and `format_bytes` keep comma thousands and `k`/`KB`/`MB`
  suffixes. Both are accepted in ja/en; no locale-specific separators are
  introduced.
- Tests for the year rail use explicit locales (`ja`, `en`) so the global
  locale cannot leak between parallel tests.

### 9. Migration strategy

Infrastructure first, then surfaces in this order, adding keys to both catalogs
as each file is touched:

1. `crates/i18n` crate + `App::set_language` + settings language card.
2. `app.rs` placeholders, `Screen::title`, `shell.rs` (navigation, sidebar,
   status card, titlebar).
3. `settings.rs`, `chrome.rs`, `palette.rs` (colour names).
4. `library.rs`, `gallery.rs`, `search.rs`, `year_rail.rs`, `viewer.rs`.
5. `dashboard.rs`, `compression.rs`, `dialogs.rs`.
6. `notifications.rs`, `import.rs`.
7. `update_view.rs`, `components.rs`, `theme.rs` (units/hints).
8. `app/*.rs` toasts, errors, confirmation text.
9. daemon tray, `Daemon::reload_settings`, schema v10, keyed daemon errors,
   and the UI-side daemon error renderer.

Each step must compile and keep Japanese output identical. A file is finished
when a grep for Japanese string literals in that file finds only tests, logs,
demo data, or comments.

Keys are written once and reused for repeated labels (`common.cancel`,
`common.retry`, etc.). Context-specific wording gets its own key rather than
reusing a generic one when the English translation would differ.

### 10. Tests

`crates/i18n/tests/catalog.rs`:

- `normalize("")`, `normalize("xx")` → `"ja"`; `normalize("en")` → `"en"`.
- `tr_in("ja", "nav.photos") == "写真"`;
  `tr_in("en", "nav.photos") == "Photos"`.
- Unknown locale falls back to Japanese.
- A missing key returns `"—"`, not the key.
- Every locale in `locales()` has a non-empty `language.name`.
- Every key in `ja.yml` exists in `en.yml`.
- Every catalog value that contains `%{...}` uses only the placeholders the
  corresponding call site passes (checked for the statically known call sites
  listed in the test; this catches copy/paste mistakes without a parser).

`crates/i18n/tests/source_keys.rs`:

- Walk `crates/ui/src` and `crates/daemon/src`, collect every literal passed to
  `tr!` and `tr_args!`, and assert it exists in `ja.yml`. This makes a typo a
  test failure instead of a runtime `"—"`.

UI tests:

- Year-rail month formatting for ja and en, including unknown months, via
  `format_captured_month_in` so parallel tests never touch the global locale.
- `UpdateNotice` renders the same structured notice in ja and en, including a
  rollback reason.
- `PhotoBrowser` label invalidation: after clearing `labels`, the next render
  rebuilds them instead of reusing the previous locale's shaped text.
- The daemon error renderer translates key+args in ja and en, and falls back
  to the stored `message` for NULL key, unknown key, invalid JSON, or a missing
  translation.
- Existing behavior tests stay unchanged except where they asserted a
  Japanese label; those assertions move to the explicit-locale helper.

Core tests:

- Schema v10 adds both columns and is idempotent when re-run.
- `record_daemon_error_i18n` round-trips key/args, and the legacy
  `record_daemon_error` leaves them NULL.
- `daemon_errors()` reads pre-v10 rows with NULL key/args.
- The existing unknown-operation test still ignores future rows.

Manual/visual QA:

- `--demo` launch, switch to English, visit Photos, Search, Compression,
  Dashboard, Settings, open the viewer, a dialog, and the notification modal.
- Confirm no raw keys, no clipped labels, and that the language survives a
  restart.
- Switch back to Japanese and confirm the original layout.

## Risks and mitigations

- **Catalog drift while migrating.** The source-key test fails on any
  `tr!("...")` missing from `ja.yml`; the ja/en parity test fails if English
  lags.
- **Global locale in parallel tests.** Production uses the global locale;
  tests use `tr_in`/`*_in` with an explicit locale. Only tests that
  deliberately switch locale run in one test function.
- **Long English strings overflow tight chips/buttons.** English is generally
  shorter than Japanese, but labels like "Compression settings" can grow.
  Visual QA covers the main screens; chips wrap.
- **Transient toast language.** A toast created before the switch keeps its
  old text until it disappears. This is expected and avoids rewriting queued
  UI state.
- **Daemon tray update timing.** The daemon notices the setting within one
  500 ms reload; a switch is not instantaneous but needs no restart.
- **Schema v10 on existing databases.** The migration is additive and nullable,
  uses the same immediate transaction as v4–v9, and is covered by a retry test.
  Old rows keep NULL key/args and fall back to `message`; no backfill is
  attempted.

## What is left to the builder

- Exact key names within the namespaces above, as long as they stay semantic
  and consistent.
- English wording, provided it is concise and matches the existing tone.
- Whether to translate a borderline technical string; the rule is "visible to
  the user in a screen, toast, dialog, tooltip, or tray" → translate.
- The order of files within a migration step, and whether to parallelize
  independent screens.

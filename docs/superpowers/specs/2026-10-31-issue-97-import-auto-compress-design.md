# Issue #97: 取り込み直後の自動圧縮ジョブ登録

## 意図

取り込み直後の写真が、自動圧縮ONかつ有効な自動プロファイルがあるのに
キューに乗らない競合を解消する。あわせて、登録件数を取り込み結果から
確認できるようにし、自動圧縮ジョブの重複登録をDBレベルで防ぐ。

## 現状

- #208 以降、取り込みは UI が先に索引せず、`ScanRoot` をデーモンへ
  要求する。デーモン稼働中の取り込みは `scan_roots_inner` が
  `new_ids` を `enqueue_auto_jobs` に渡すため、自動圧縮に乗る。
- デーモン停止中に取り込み、起動時のフルスキャンが先に索引した場合、
  空ライブラリでは `initial_scan = true` となり、既定の
  `auto_compress_backlog = false` で enqueue されない。後から処理される
  `ScanRoot` は既に索引済みのため `new_ids` が空になり、ジョブが残らない。
- `enqueue_auto_jobs` は同じ写真・プロファイルの既存ジョブを確認しない。
  現行経路では `new_ids` が重複を防いでいるが、DBレベルでは保証されない。
- 取り込み結果には自動圧縮へ追加した件数が出ず、デーモンログにも残らない。

## ゴール

- デーモン稼働中・停止中のどちらで取り込んでも、新規写真が自動圧縮対象になる。
- `auto_compress_immediate` に従い `pending` / `waiting` を選ぶ。
- 同じ写真・プロファイルの自動圧縮ジョブを二重登録しない。
- 取り込み結果パネルに「自動圧縮に N 件追加」を表示し、デーモンログにも
  写真数と登録ジョブ数を残す。
- `auto_compress_backlog = false` のとき、初回スキャンで見つかった
  既存写真（バックログ）は従来どおり圧縮しない。
- 自動圧縮OFF、または有効な自動プロファイルが無いときは何もしない。

## 非ゴール

- 取り込み処理そのものへの圧縮機能の追加。
- 失敗した自動圧縮ジョブの自動再試行。
- watcher の増分索引経路の変更。
- UI が写真を先に索引してジョブを登録する方式への回帰。
- 手動圧縮の重複ジョブ仕様の変更（同じ写真・プロファイルを意図的に
  複数回積む既存動作は維持する）。

## 方針

### 1. 起動時のコマンド処理順

`Daemon::run` の起動シーケンスで、初回フルスキャンより前に保留中の
デーモンコマンドを処理する。初回スキャン判定はコマンド処理前の
`count_photos() == 0` で固定し、フルスキャンへ明示的に渡す。

- 空ライブラリで起動した場合、キュー済みの `ScanRoot` を先に実行する。
  `ScanRoot` は `full_scan = false` なので、バックログ設定に関わらず
  取り込み写真を enqueue する。
- 起動時のフルスキャンは「初回スキャン」のまま扱い、他のルートに
  残っている既存写真のバックログは enqueue しない。
- 同じ起動バッチに `Rescan` と `ScanRoot` が混在する場合は、取り込み分を
  先に索引できるよう `ScanRoot` を先に処理する。
- `run_once` も同じ判定を使い、テスト可能な起動処理に切り出す。

### 2. 自動圧縮 enqueue の冪等化

`Db` に自動圧縮専用の enqueue メソッドを追加し、同一 `photo_id` +
`profile_id` のジョブが既に存在する場合は挿入しない。手動圧縮用の
既存メソッドは変更しない。

`enqueue_auto_jobs` は登録したジョブ数を返し、呼び出し側はログに
写真数・プロファイル数・登録数を出す。`ScanRoot` / フルスキャン /
watcher の全経路で同じ関数を使う。

### 3. 取り込み結果への件数表示

- IPC の `Event::ScanFinished` に `auto_enqueued` を追加する。
- デーモンはスキャン中に enqueue したジョブ数をイベントへ載せる。
- UI は取り込み後に `ScanRoot` を要求したとき「取り込みスキャン待ち」を
  立て、次の `ScanFinished` の `auto_enqueued` を取り込み結果へ加算する。
- 取り込み結果パネルに `自動圧縮に N 件追加` を表示する。
  N が 0 のときは表示しない。
- デーモンログにも同じ件数を残す。

## テスト

- 空ライブラリ・バックログOFFで、停止中取り込み相当の `ScanRoot` が
  起動時フルスキャンより先に処理され、取り込み写真だけが enqueue され、
  既存ルートの写真は enqueue されないこと。
- 自動圧縮 enqueue を同じ写真・プロファイルで2回呼んでもジョブが
  増えないこと。
- `auto_compress_immediate = false` で `waiting`、`true` で `pending` に
  なること（既存テストの維持）。
- 取り込み結果の件数加算と、0件時の非表示をUIの純粋関数で検証する。

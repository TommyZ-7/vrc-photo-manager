**Goal:** Align architecture docs, the IPC spec/plan, and two Rust doc comments with the current implementation.

**Architecture:** Documentation and doc-comment edits only, plus removal of three unused `ErrorCode` variants. No runtime behavior changes and no IPC wire changes.

**Tech Stack:** Rust stable (edition 2024), Markdown docs, cargo.

**Spec:** `docs/superpowers/specs/2026-10-31-docs-reconciliation-58-67-212-214-design.md`

## Global Constraints

- The implementation is canonical for #67: a mismatch returns the versioned `hello` response, then closes. Do not add a `protocol_mismatch` error response.
- Keep the UI message 「デーモンの更新が必要です」 working through `IpcError::ProtocolMismatch`.
- Do not modify `opencode.json` or unrelated user files.
- Commit prefixes: `docs:` for documentation, `chore:` for doc-comment/code cleanup.
- Run `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, and `cargo test --workspace` before the PR.

## Review Focus

- A version-mismatched old client must still reach the update message; the existing `protocol_mismatch_is_reported` client test and `protocol_mismatch_reports_the_update_message` UI test must stay green after removing `ErrorCode::ProtocolMismatch`.
- The `ErrorCode` enum must keep exactly the variants the server emits; no `ErrorCode::ProtocolMismatch` / `UnknownRequest` / `Internal` references may remain.
- Dashboard docs must match the rendered labels: 写真 / 未完了ジョブ / ライブラリ容量 / デーモン.
- `request_import_scan` must keep a one-line doc, and `add_photo_root_and_save` must own the save/restore explanation.

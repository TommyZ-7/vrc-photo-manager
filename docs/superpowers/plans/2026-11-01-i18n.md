# English UI (i18n) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add a shared ja/en catalog and make every user-facing UI surface, the daemon tray, and stored daemon errors follow `settings.language`, with Japanese fallback and data-only language addition.

**Architecture:** New `vrc-photo-i18n` crate wraps `rust-i18n` and owns catalog discovery, fallback, and `tr!`/`tr_args!`. UI and daemon call it; Settings switches the global locale at runtime. Schema v10 stores daemon error keys + JSON args so stored errors render in the current language.

**Tech Stack:** Rust 2024, rust-i18n 4.2, GPUI/gpui-kit 0.8, SQLite/rusqlite, serde_json.

**Spec:** `docs/superpowers/specs/2026-11-01-i18n-design.md`

## Global Constraints

- New crate: `crates/i18n`, package `vrc-photo-i18n`, crate name `vrc_photo_i18n`.
- `rust-i18n = "4.2"` (same major as gpui-component 0.8.1).
- Catalog files use `_version: 1`, flat dot-separated keys, `%{name}` placeholders.
- Japanese is the default and the source of truth. English must be complete; a missing key falls back en → ja → `—`, never to the key.
- `AppSettings.language` stays a `String`; unknown or empty values normalize to `ja`.
- No `if language == "en"` branches in screens. Language-specific data lives in the catalog.
- Do not translate tests, logs, demo data, file paths, user data, core error details, compression job error details, or arbitrary `ScanFailure.message` text.
- The migration ships as one PR. Do not merge a state with a live selector and a half-translated English UI.
- Run `cargo fmt --all -- --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace` before pushing.
- Commit prefixes: `feat:`, `fix:`, `docs:`, `ci:`, `chore:`.

## Review Focus

- An unknown, empty, or regional `settings.language` (`fr`, ``, `en-US`) must start in Japanese (or the base language) without crashing; the selector must not show a raw code as the only label.
- A missing English key must fall back to Japanese; a key missing everywhere must render `—`, never `photos.empty`. This is the acceptance condition most likely to regress as keys are added.
- Switching language while a photo grid is mounted must rebuild the year-rail's shaped labels; otherwise the old month language survives until the next index change.
- A pre-v10 database with stored daemon errors must migrate without losing rows, and an error with NULL key/args must still display its `message`.
- English labels must fit the existing settings chips, sidebar, buttons, and dialogs without clipping or overlapping at 1280×820 and 1440×900.

- [x] **Step 5: Implement the wrapper API**

In `crates/i18n/src/lib.rs`, call `rust_i18n::i18n!("locales", fallback = "ja");` at crate root. Implement:

- `LOCALE_SET: AtomicBool` so `current_locale()` returns `DEFAULT_LOCALE` until `set_locale` is called; this keeps `tr()` Japanese by default even though `rust_i18n::locale()` starts at `"en"`.
- `available()`: `_rust_i18n_backend().available_locales()`.
- `lookup_exact(locale, key)`: `_rust_i18n_backend().translate(locale, key).map(Cow::into_owned)`.
- `resolve(code)`: exact match, then base language before `-`, then `None`.
- `normalize(code)`: `resolve(code).unwrap_or_else(|| DEFAULT_LOCALE.to_string())`.
- `tr_in(locale, key)`: resolve the locale, then exact → base → `DEFAULT_LOCALE`; return `MISSING` and `tracing::warn!` when all miss.
- `tr_args_in`: call `tr_in`, then `rust_i18n::replace_patterns`.
- `locales()`: discover codes, sort with `ja` first, label with exact `language.name` lookup or the code.
- `keys(locale)`: `_rust_i18n_backend().messages_for_locale(locale).map(|rows| rows.into_iter().map(|(k, _)| k.into_owned()).collect()).unwrap_or_default()`.
- `has_key(locale, key)`: `lookup_exact(locale, key).is_some()`.
- Macros:

```rust
#[macro_export]
macro_rules! tr {
    ($key:literal $(,)?) => {
        $crate::tr($key)
    };
}

#[macro_export]
macro_rules! tr_args {
    ($key:literal $(,)?) => {
        $crate::tr($key)
    };
    ($key:literal, $($name:ident = $value:expr),+ $(,)?) => {
        $crate::tr_args($key, &[$((stringify!($name), ($value).to_string())),+])
    };
}
```

## 1. エグゼクティブサマリ

本アプリは、VRChatで撮影した写真を「撮影時の文脈」ごと蓄積・検索・圧縮するデスクトップソフトである。

VRChatの写真ファイル名には日時と解像度しかない。撮影したワールド、同接していたプレイヤー、インスタンスは写真だけでは分からない。VRChat本体のXMPメタデータは撮影者とワールド名だけを保持し、他プレイヤーは含まない。公式WebSocket（pipeline）もワールドや同接者を配信しない。

そこで本アプリは、常駐プロセスがVRChatの出力ログを監視し、ワールド遷移とプレイヤーの入退室を時系列で記録する。写真の撮影時刻と突き合わせることで、写真ごとに「いつ・どこで・誰と撮ったか」をローカルDBに保存する。さらに既存の圧縮機能を移植し、新規写真の自動圧縮と、選択した写真の手動圧縮を提供する。

写真ファイルは原則として移動しない。VRChatの写真フォルダを参照し、DBに索引を持つ。必要な写真だけ任意で管理フォルダへ取り込める。

## 2. 背景と課題

### 2.1 ユーザーの課題

- 写真が増えると「あのワールドの写真」「あの人と行ったイベントの写真」を探せない。
- VRChatの写真はPNGで容量が大きく、SSDを圧迫する。
- 既存の圧縮ツールは圧縮はできるが、写真の文脈管理はできない。
- VRCX等のログツールはワールド履歴やフレンド管理には強いが、写真ライブラリとしての一覧・検索・圧縮は主目的ではない。

### 2.2 技術的な制約（重要）

| 項目 | 事実 | 本アプリでの扱い |
|---|---|---|
| VRChatのXMPメタデータ | 2025.3.2以降、カメラ設定でON（既定ON）。撮影者とワールドのID/名前を保存。他プレイヤーは保存しない。プライベートワールドはID/名前も保存しない。 | 補完情報として読む。無い場合はログで補う。 |
| VRChat公式WebSocket（pipeline） | `wss://pipeline.vrchat.cloud` は受信専用のAPIイベント。フレンド状態、通知、ユーザー更新など。ワールド・インスタンス・同接プレイヤーは配信しない。認証Cookieが必要。 | MVPでは採用しない。写真の文脈取得には使えないため。 |
| VRChat出力ログ | `output_log_yyyy-MM-dd_HH-mm-ss.txt`。ワールド参加、`OnPlayerJoined` / `OnPlayerLeft`、シーン離脱などを記録。**VRChat本体が24時間で削除する。** | 常駐プロセスで解析し、解析済みイベントをDBに永続化する。 |
| ログのワールド名 | 参加ログはワールドIDとインスタンスIDが中心。表示名はログに無い場合がある。 | XMPの表示名、`Joining or Creating Room` 行、手動エイリアスで補完。名前が無い場合はIDを表示。 |
| VRChat写真のファイル名 | `VRChat_YYYY-MM-DD_HH-MM-SS.mmm_WxH.png`（ローカル時刻）。 | 撮影時刻の第一情報として使う。解析できない場合はファイル更新時刻を使う。 |

## 3. プロダクト概要

### 3.1 価値提案

1. **文脈で探せる**: ワールド、プレイヤー、日時、タグ、お気に入りで写真を絞り込める。
2. **撮った瞬間の情報が残る**: 常駐監視により、VRChatのログが消えた後も「その時の情報」がDBに残る。
3. **容量を自動で削減**: 既存のJPEG / WebP / AVIF / JPEG XL圧縮を新規写真に自動適用できる。手動では元画像の扱いを都度選べる。
4. **ローカル完結**: アカウント連携なし、テレメトリなし、ネットワーク送信なし。

### 3.2 対象ユーザー

- VRChatをPC（WindowsまたはLinux/Proton）でプレイし、写真を大量に撮るユーザー。
- VRC写真部、イベント主催者、ワールド巡りを記録したいユーザー。
- 既存の圧縮ツールを使っているが、写真の整理・検索に不満があるユーザー。

### 3.3 非目標（MVPではやらない）

- VRChatアカウントログイン、フレンド管理、通知、インバイト操作。
- 公式WebSocket（pipeline）への接続。
- クラウド同期、SNS投稿、アップロード。
- 写真編集（トリミング、色補正、合成）。
- 顔認識、自動タグ付け、AI検索。
- 完全削除（MVPはOSゴミ箱への移動のみ）。
- macOS対応。

### 4.1 自動圧縮と「都度選択」の整合

自動圧縮のたびにダイアログを出すと撮影体験を壊すため、次のように役割を分ける。

- **自動圧縮**: 新規検知した写真に対し、有効なプロファイルを適用して別ファイルを生成する。元画像は必ず残す。
- **手動圧縮**: 一覧または詳細から実行し、その場で「元画像を保持 / 置換（元画像はゴミ箱へ）/ 圧縮版のみ」を選ぶ。
- **置換**を選んだ場合も、いきなり削除しない。圧縮ファイルのデコード検証に成功した後、元画像をOSゴミ箱へ移動する。

## 5. 機能要件

### 5.1 写真一覧

- サムネイルグリッド表示。列数はウィンドウ幅とサムネイルサイズ設定に応じて自動計算。
- 並び順: 撮影日時（新しい順/古い順）、ファイルサイズ、ワールド名、追加日時。
- 日付またはワールドでのグループ表示（切り替え可能）。
- 各セルに以下を表示:
  - サムネイル
  - 撮影日時
  - ワールド名（無ければID）
  - 圧縮済みバッジ
  - 文脈未紐付けバッジ
  - お気に入り
- 複数選択（Ctrl/Cmd、Shift）、全選択、選択解除。
- 右クリックメニュー: 開く、フォルダを開く、圧縮、タグ付け、お気に入り、ゴミ箱へ移動、パスをコピー。
- ドラッグ＆ドロップでの取り込み（任意）。
- 空状態、読み込み中、ファイル欠損状態を表示。
- 新規写真の検知時は、現在のフィルタを維持したまま一覧に反映する。

### 5.2 写真詳細

- 大きなプレビュー（画面-fit / 等倍 / ズーム）。8K写真はフルデコードせず、最大2048pxのプレビューを生成して表示する。「元画像を開く」で外部アプリに渡す。
- メタデータパネル:
  - 撮影日時（ローカル、タイムゾーンオフセット）
  - ファイルパス、ファイルサイズ、解像度、ハッシュ
  - ワールド名 / ワールドID / インスタンスID
  - 撮影者（XMPがある場合）
  - 撮影時の同接プレイヤー一覧（ユーザーID付き）
  - 情報の取得元（ログ / XMP / 両方 / 手動）と信頼度
- タグ、お気に入り、メモの編集。
- 圧縮履歴: 元ファイルと生成物、プロファイル、削減量。
- 操作: 圧縮、置換、ゴミ箱へ移動、フォルダを開く、パスをコピー。
- 「同じセッションの写真」を下部に表示（同じワールド滞在の前後写真）。MVPに含めるが、重ければ後回し可。
- 文脈が未紐付けの場合は「再紐付け」ボタンと、手動でワールド/プレイヤーを補正する導線を用意する。

### 5.3 圧縮設定

既存の `CompressionProfile` を踏襲する。

| 設定 | 内容 |
|---|---|
| プロファイル名 | 任意 |
| 有効/無効 | 自動圧縮の対象にするか |
| 形式 | JPEG / WebP / AVIF / JPEG XL |
| 品質 | 1〜100 |
| ロスレス | WebP / AVIF / JXL。JPEGは非対応 |
| エンコード速度 | AVIF / JXLのみ 1〜10 |
| リサイズ | 有効/無効、幅、高さ、アスペクト比維持 |
| 出力先 | 未指定なら元ファイルの `compressed/` |
| サフィックス | 出力ファイル名に付与 |
| 自動圧縮 | 新規写真に適用するか（プロファイル単位） |

- プロファイルの追加、複製、削除、並び替え、有効/無効。
- 出力ファイル名の衝突回避。ソースと同じパスになる場合は必ずサフィックスを付けるかスキップする。
- 手動実行ダイアログ:
  - 使用プロファイル（複数選択可）
  - 元画像: 保持 / 置換（ゴミ箱へ）/ 圧縮版のみ
  - 既存出力がある場合: スキップ / 上書き / 連番
- キュー画面: 待機、実行中、完了、失敗、キャンセル、再試行。進捗と削減量を表示。
- 統計: 総圧縮数、元サイズ合計、圧縮後サイズ合計、削減率、プロファイル別。DBから集計する。

形式ごとの注意:

| 形式 | 透過 | ロスレス | 速度指定 | 備考 |
|---|---|---|---|---|
| JPEG | 非対応 | 非対応 | なし | 透過は背景合成される |
| WebP | 対応 | 対応 | なし | |
| AVIF | 対応 | 対応（移植時に修正） | 1〜10 | 現行コードは lossless 時に品質100にするだけで真のロスレスではない |
| JPEG XL | 対応（現行コードはαを落とす） | 対応 | 1〜10 | `jpegxl-rs` のα不具合回避のためRGBでエンコードしている。UIで警告する |

### 5.4 検索

- 検索条件:
  - ワールド（複数選択、名前またはIDの部分一致）
  - プレイヤー（複数選択、表示名またはユーザーIDの部分一致）
  - 日時（プリセット: 今日、直近7日、今月、今年、カスタム範囲）
  - タグ（複数選択）
  - お気に入り
- カテゴリ間はAND、カテゴリ内はOR。
- 選択中の条件をチップで表示し、個別解除・全解除できる。
- ワールド/プレイヤーの入力候補はDBから取得。100k規模でも候補数は限定されるため、`LIKE` 検索で実用速度を目標とする。
- 検索結果件数と、「文脈未紐付け」件数を表示する。
- 最後の検索条件を保存し、次回起動時に復元する（設定で無効化可能）。
- フリーテキスト検索（メモ、ファイル名、タグ名の全文検索）はMVP外。必要になった時点でSQLite FTS5を追加する。

### 5.5 ログ監視と情報の紐付け

#### 5.5.1 監視プロセス

- UIとは別プロセスで常駐する。ユーザーセッションで動作し、OSサービスにはしない。
- トレイアイコンからUIを開く、監視の一時停止/再開、終了ができる。
- OSログイン時に自動起動する（設定で無効化可能）。
- 二重起動を防止する（単一インスタンス）。
- UIが起動していない間も監視と自動圧縮を継続する。

#### 5.5.2 監視対象

- VRChatログディレクトリ:
  - Windows: `%USERPROFILE%\AppData\LocalLow\VRChat\VRChat`
  - Linux/Proton: `steamapps/compatdata/438100/pfx/drive_c/users/steamuser/AppData/LocalLow/VRChat/VRChat`
  - Steamライブラリの場所は `libraryfolders.vdf` から探索する。Flatpak版Steamのパスも候補に含める。
  - 自動検出に失敗した場合は手動指定。
- 写真ディレクトリ:
  - Windows: `%USERPROFILE%\Pictures\VRChat`
  - Linux/Proton: 上記プレフィックス内の `drive_c/users/steamuser/Pictures/VRChat`
  - 複数ルートを登録可能。VRChat設定で変更している場合も追加できる。

#### 5.5.3 ログ解析

1行の形式:

```text
2026.10.21 21:23:12 Debug -  [Behaviour] Joining wrld_xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx:12345~region(jp)
2026.10.21 21:23:20 Debug -  [Behaviour] OnPlayerJoined DisplayName (usr_xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx)
2026.10.21 21:45:01 Debug -  [Behaviour] OnPlayerLeft DisplayName (usr_xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx)
2026.10.21 22:10:00 Debug -  [Behaviour] Unloading scenes
```

解析するイベント:

| イベント | ログの目印 | 状態更新 |
|---|---|---|
| ワールド参加 | `[Behaviour] Joining wrld_...` | 新セッション開始。前セッションを閉じる。ワールドID/インスタンスIDを保存 |
| ワールド名ヒント | `Joining or Creating Room: ...` | 表示名のヒントとして保存（存在する場合のみ） |
| プレイヤー参加 | `OnPlayerJoined <name> (usr_...)` | セッション参加者に追加 |
| プレイヤー退出 | `OnPlayerLeft <name> (usr_...)` | 退出時刻を記録 |
| ワールド退出 | `Unloading scenes` | セッション終了 |
| ログ終了/新ファイル | ファイル切替 | 開いているセッションを閉じる |

- タイムスタンプはローカル時刻。UTCオフセットも併記して保存する。
- ユーザーIDが取れない古いログでは、表示名をキーにする。
- 表示名の変更はユーザーID単位で最新名を保持する。
- 解析できない行は無視し、件数だけ diagnostics に記録する。
- 追記はファイル末尾のオフセットをDBに保存し、再起動時に続きから読む。VRChatがファイルを掴んでいても読めるよう、読み取り専用・共有モードで開く。
- ログファイルの検知は `notify`、追記の読み取りは250〜500msのポーリングを併用する（Windowsのファイルロック対策）。

#### 5.5.4 写真とログの紐付け

1. 写真検知時、ファイル名から撮影時刻を解析する。
   - 正規表現: `^VRChat_(\d{4})-(\d{2})-(\d{2})_(\d{2})-(\d{2})-(\d{2})\.(\d{3})_(\d+)x(\d+)\.(png|jpe?g)$`
   - 失敗時はファイル更新時刻を使い、`link_method=file_mtime` とする。
2. 撮影時刻を含むセッションを探す。
   - `started_at <= captured_at < ended_at`（終了していないセッションは現在時刻まで）。
   - 見つからない場合、前後3秒以内のセッション境界を「推定」として低信頼度で紐付ける（設定で無効化可能）。
3. その時刻に在室していたプレイヤーを取得する。
   - `joined_at <= captured_at` かつ（`left_at IS NULL` または `captured_at < left_at`）。
4. XMPを読む。
   - PNGの `iTXt` / `tEXt` から `XML:com.adobe.xmp` を取得。
   - `vrc:WorldDisplayName`、`Author` などの既知フィールドを読む。実キーは実ファイルで検証する。
   - XMPのワールド名をログのワールドIDに紐付ける。XMPしか無い場合は `world_source=xmp` の合成コンテキストを作る。
5. 紐付け結果を `photo_context` と `photo_players` に保存する。
   - 信頼度: `log+xmp`（高）、`log`（中）、`xmp`（低）、`none`。
6. 文脈が未紐付け、または低信頼度の写真は再紐付けキューに入れる。新しいセッション/プレイヤーイベントが入るたび、または手動の「再紐付け」で再計算する。

時刻の扱い:

- ログとファイル名は同じマシンのローカル時刻なので、タイムゾーン変換せずに比較する。
- 保存時はローカル時刻文字列とUTCエポック、その時点のUTCオフセットを保存する。
- サマータイムやタイムゾーン変更で過去のローカル時刻が曖昧になるため、UTC変換は表示用に限定する。

#### 5.5.5 過去ログの一括復元

- 起動時または手動操作で、存在する `output_log_*.txt` をすべて解析する。
- 解析済みイベントをDBに保存し、既存の全写真を撮影時刻で再紐付けする。
- **VRChatはログを24時間で削除する。** したがって初回の一括復元で対象になるのは、実行時に残っているログの範囲だけである。
- 以後は常駐プロセスが起動している限りイベントが蓄積される。生ログは保存しないため、VRChatが削除したログの再解析はできない。
- 復元結果（解析ログ数、紐付いた写真数、未紐付け数、解析不能行数）をUIに表示する。
- パーサのバージョンを `log_imports` に保存し、パーサ更新時に「保存済みイベントから再紐付け」できるようにする。生ログが無くても、イベントDBから写真リンクは再構築できる。

### 5.6 任意のライブラリ取り込み

- 参照方式が既定。VRChatの写真フォルダは監視するだけで、ファイルを移動しない。
- 写真またはフォルダを選んで「ライブラリへ取り込み」できる。
- 取り込み時にコピー / 移動を都度選択（既定はコピー）。
- 管理フォルダは設定で指定。取り込み後も元の撮影日時・XMP・ファイル名を保持する。
- 取り込み先で名前が衝突する場合は連番を付ける。
- 参照ファイルが見つからない場合は `missing` としてDBに残し、勝手に削除しない。再スキャンで復帰できる。

### 5.7 写真の削除

- OSのゴミ箱へ移動する（Windows: ごみ箱、Linux: freedesktop.org Trash仕様）。
- 削除前に確認ダイアログを出す。複数選択時は件数を明示する。
- ゴミ箱への移動に成功した場合のみDBから削除（または `deleted` 状態に）する。
- 完全削除は提供しない。必要な場合はOSのごみ箱を空にする。

### 5.8 トレイ常駐と設定

- トレイメニュー:
  - UIを開く
  - 監視を一時停止 / 再開
  - 現在の状態（監視中、ワールド名、同接人数）
  - 設定を開く
  - 終了
- トレイのツールチップに監視状態を表示。
- UIを閉じても監視プロセスは残る。
- 設定項目:
  - 写真ルート、VRChatログパス（自動/手動）
  - 自動起動のON/OFF
  - 言語（日本語/English）
  - テーマ（ダーク/ライト/システム）
  - サムネイルキャッシュ上限（既定2GB）
  - 自動圧縮のON/OFF、バックログ（初回スキャン分）も圧縮するか（既定OFF）
  - 圧縮ワーカー数（既定1）
  - 推定紐付けの許可（既定ON）
  - 解析イベントの保持期間（既定: 無期限。削除機能あり）
  - 診断情報の表示（DBサイズ、未解析行数、最終ログ解析時刻）
  - データのエクスポート/インポート（設定とタグ。写真ファイルは含めない）

### 5.9 国際化

- 日本語と英語を切り替え可能。既定はOSロケール。
- UI文言は `rust-i18n` のYAMLカタログで管理する。
- 日時・ファイルサイズ・数値の表示はロケールに合わせる。
- ログの表示名やワールド名は翻訳しない。

## 6. 非機能要件

### 6.1 性能目標（10万枚）

| 項目 | 目標 |
|---|---|
| 起動から一覧の初期表示 | ウォーム1.5秒以内、コールド5秒以内 |
| 検索・フィルタ適用 | 150ms以内（10万枚、インデックス利用時） |
| グリッドスクロール | 60fps（可視範囲のみ描画） |
| サムネイル表示 | キャッシュ済み100ms以内、未生成500ms以内 |
| 常駐メモリ | 500MB以下（プレビュー画像を除く） |
| サムネイルキャッシュ | 既定2GB、LRUで削除 |
| DBサイズ | 10万枚で300MB以下（イベント含む）を目標 |

### 6.2 信頼性

- 圧縮は一時ファイルに書き、検証後にリネームする。途中失敗で元画像を壊さない。
- 置換時は圧縮ファイルのデコード検証後に元画像をゴミ箱へ移動する。
- DBはWALモード、`busy_timeout` 5秒。重い書き込み（ログイベント、写真索引、圧縮ジョブ）はデーモンに集約し、UI発のタグ・お気に入り・メモは短いトランザクションで書く。
- スキーママイグレーションは起動時に自動実行。失敗時はバックアップから復旧できる。
- ファイル監視のイベント取りこぼしに備え、起動時と手動再スキャンで差分を拾う。
- ログ追記のオフセットを保存し、再起動時に重複解析を避ける。

### 6.3 プライバシー・セキュリティ

- ネットワーク通信なし。テレメトリなし。アカウント認証情報を保存しない。
- 保存するのは解析済みイベント（ワールドID/名前、プレイヤーのユーザーID/表示名、日時）のみ。生ログは保存しない。
- 表示名・ユーザーIDは個人情報になり得る。エクスポート時には注意書きを表示する。
- データ削除機能: DBとサムネイルキャッシュを削除する。写真ファイルは削除しない。
- IPCはローカルユーザーのみがアクセスできる名前付きパイプ / Unixドメインソケットを使い、ネットワークに公開しない。
- 依存クレートのライセンス（Apache-2.0 / MIT / BSD系）を確認し、NOTICEを同梱する。

### 6.4 アクセシビリティ

- `gpui-kit` のAccessKit対応を利用し、キーボード操作とスクリーンリーダーの基本動作を確保する。
- フォーカスリング、コントラスト、キーボードショートカットを用意する。
- 色だけで状態を伝えない（バッジにはテキストも付ける）。

### 6.5 対応環境

- Windows 10/11（x64）。DirectX 12対応GPUを推奨。
- Linux（x64）。Wayland/X11、Vulkanドライバが必要。Steam DeckのProton環境を想定。
- Rust stable（edition 2024）。MSVCツールチェーン（Windows）、CMakeとC++コンパイラ（JPEG XLのvendoredビルド用）。

## 7. アーキテクチャ

### 7.1 全体構成

```text
┌─────────────────────────────┐        ┌──────────────────────────────┐
│ UIプロセス (gpui-kit)        │        │ デーモンプロセス              │
│                             │  IPC   │                              │
│ 写真一覧 / 詳細 / 検索       │<------>│ ログ監視 / 写真監視            │
│ 圧縮設定 / キュー / 設定     │ JSON   │ 文脈紐付け / 自動圧縮          │
│                             │ lines  │ トレイ / 自動起動              │
└──────────────┬──────────────┘        └──────────────┬───────────────┘
               │                                      │
               │ 読み取り / 短い書き込み                │ 書き込み
               ▼                                      ▼
        ┌──────────────────────────────────────────────────┐
        │ SQLite (WAL)  +  サムネイルキャッシュ (WebP)       │
        └──────────────────────────────────────────────────┘
               ▲                                      ▲
               │                                      │
        VRChat写真フォルダ                     VRChatログ / XMP
```

- UIとデーモンは同一バイナリの別サブコマンドでもよいが、配布とプロセス分離を明確にするため**別バイナリ**とする。
  - `vrc-photo-manager`（UI）
  - `vrc-photo-manager-daemon`（トレイ常駐）
- 共有コードは `core` クレートに置く。UIはDBを直接読む（WALの並行読み取り）。書き込みは原則デーモン経由。タグ・お気に入りなどUI発の短い書き込みは、busy_timeout付きで直接行う。
- UI起動時にデーモンが居なければ起動を試み、IPCの接続を待つ（タイムアウト5秒）。接続できなくてもDBの読み取りだけで閲覧は可能。

### 7.2 IPC

- トランスポート: `interprocess` クレート（Windows名前付きパイプ / Unixドメインソケット）。
- プロトコル: 改行区切りJSON。`Request` / `Response` / `Event`。
- 主なコマンド:
  - `Status`
  - `Pause` / `Resume`
  - `Rescan { roots }`
  - `Relink { photo_ids? }`
  - `Import { paths, mode }`
  - `Compress { photo_ids, profile_ids, policy }`
  - `CancelJob { job_id }`
  - `OpenDataDir`
- 主なイベント:
  - `PhotoAdded` / `PhotoUpdated`
  - `ContextLinked`
  - `CompressionProgress` / `CompressionFinished`
  - `WatcherStatus`
- バージョンハンドシェイクを行い、UIとデーモンのバージョン不一致時は再起動を促す。

> **実装状況（2026-10-24）**: 最初のスライスとして `crates/ipc`、ローカルソケット、改行区切りJSON、バージョンハンドシェイク、`status` / `wake_commands` / `wake_jobs` / `set_paused` / `shutdown` / `subscribe`、スキャン/圧縮/エラー/状態イベントを実装した（ADR-0011）。コマンドはSQLiteの `daemon_commands` を正とし、IPCはwake-upだけを担当する。`Import` / `Compress` / `CancelJob` / `OpenDataDir`、`PhotoAdded` / `PhotoUpdated` / `ContextLinked` / `WatcherStatus`、UI起動時の5秒待ちは未実装で、将来拡張とする。詳細は [設計書](superpowers/specs/2026-10-24-daemon-ipc-design.md) を参照。

SQLiteを使用する。主要テーブル:

| `derivatives` | 圧縮生成物 | id, photo_id, path, format, width, height, file_size, profile_id, policy, created_at |

| `instances` | インスタンス | id, world_id, instance_id, first_seen, last_seen |
| `sessions` | VRChat滞在 | id, log_file, started_at, ended_at, world_id, instance_id |
| `session_players` | 滞在者の入退室 | id, session_id, user_id, display_name, joined_at, left_at |
| `photo_context` | 写真の文脈 | photo_id, session_id, world_id, instance_id, link_method, confidence, linked_at |

インデックス:

```sql
CREATE INDEX idx_photos_captured ON photos(captured_at_utc DESC);
CREATE INDEX idx_photos_favorite ON photos(is_favorite) WHERE is_favorite = 1;

```

- パスはルートからの相対パスを正とする。絶対パスは表示・外部連携用に併記する。
- 同一ファイルの重複登録を防ぐため、`abs_path` にUNIQUE制約を置く。移動検知は `(file_size, mtime, blake3)` で行う。
- 10万枚を想定し、一覧の全件取得は軽量な `PhotoRow`（id, path, captured_at, world_name, flags）に限定する。詳細は選択時に取得する。
- 画像のフルハッシュは初回登録時ではなく、バックグラウンドで計算する（既定はサイズ+mtime、必要時のみblake3）。

### 7.5 圧縮パイプライン

既存の `src-tauri/src/compressor.rs` を `core::compress` に移植する。

```text
decode (image / jxl-oxide)
  → resize (Lanczos3, optional)
  → encode (jpeg / webp / ravif / jpegxl-rs)
  → temp file
  → decode verify
  → fsync + rename
  → DB derivative insert
  → optional: original to trash (manual replace only)
```

- 出力パスの決定:
  - `output_dir` があればそこへ。
  - なければ元ファイルの `compressed/` 配下。
  - ファイル名は `{stem}{suffix}.{ext}`。
  - 出力パスがソースと同一になる場合は、サフィックスを強制するかジョブを失敗させる。
- 既存出力がある場合のポリシー: `skip`（既定）/ `overwrite` / `suffix_number`。
- 圧縮ワーカーは既定1。CPUとメモリを考慮し、設定で最大4。
- ジョブはDBに永続化し、デーモン再起動後に `pending` / `processing` を復旧する。`processing` は `pending` に戻す。
- キャンセルはジョブ単位。エンコード中の強制中断はワーカーの完了後に反映する。
- 自動圧縮は「デーモン起動後に新規検知した写真」を対象とする。初回スキャン分も圧縮したい場合は設定でONにする（既定OFF）。
- 自動圧縮の対象プロファイルは `enabled && auto_enabled`。複数該当する場合は順に実行し、出力名の衝突を事前検証する。
- 統計は `derivatives` と `compression_jobs` から集計する。既存の `stats.json` は初回起動時にインポートし、以後はDBを正とする。

### 7.6 サムネイルと画像表示

- サムネイル: 長辺256pxのWebP。`%LOCALAPPDATA%/VrcPhotoManager/thumbnails/`（Linuxは `$XDG_CACHE_HOME`）に保存。
- 生成はバックグラウンドのワーカープール（既定 `min(4, CPUコア数-1)`）。可視範囲と前後2画面を優先する。
- デコード:
  - PNG/JPEG/WebP: `image`
  - AVIF: `gamut-avif`（純Rust）または `image` の `avif-native`（libdav1d）。`image` の `avif` featureは**エンコード用**（ravif）であり、デコードには使えない点に注意
  - JXL: `jxl-oxide`
- VRChatの元写真はPNGのため、通常の一覧表示はPNGデコードだけで完結する。AVIF/JXLのデコードは、元写真がその形式の場合と、圧縮版のプレビューを表示する場合にのみ必要。
- UIへ渡すのはデコード済みの `RenderImage`。デコード済みLRUをメモリに保持し、上限を設定する（既定256MB）。
- 詳細プレビューは長辺2048px。元画像を直接UIスレッドでデコードしない。
- サムネイル生成に失敗した場合はプレースホルダを表示し、詳細でエラーを確認できるようにする。

### 7.7 UI構成（gpui-kit）

- `gpui-kit` 0.8（`gpui-component` を含む）を採用する。GPUI本体は`gpui-kit`が再エクスポートする`gpui-pre` 0.3.9（Zed 2026-10-10スナップショット）を使い、アプリから直接`gpui`クレートに依存しない。
- 活用する部品:
  - `VirtualList` / `v_virtual_list`: 写真グリッドの仮想化
  - `Input` / `Textarea`: 検索、タグ、メモ。IME対応の修正が入っている
  - `DatePicker` / `Calendar`: 撮影日時の範囲指定
  - `Dialog` / `Sheet`: 圧縮実行、削除確認、設定
  - `Command`: コマンドパレット（将来）
  - `Sidebar` / `Dock`: 左ナビゲーションと詳細ペイン
  - `DataTable`: 圧縮履歴、診断情報などの表形式表示
  - `Theme` / `Icon` / `Tooltip` / `Badge` / `Progress`: 共通UI
  - AccessKit、`rust-i18n`、UI統合テスト
- 写真グリッドは`VirtualList`の行を自前のグリッドセル（サムネイル＋バッジ＋日時）で構成する。`DataTable`は写真一覧には使わない（セル内の画像描画と可変列に向かないため）。
- 画面:
  - 写真一覧（メイン）
  - 写真詳細（右ペインまたは全画面）
  - 圧縮設定
  - 検索/フィルタパネル（一覧に統合）
  - 設定
  - 圧縮キュー（モーダルまたは下部ドック）
- レイアウト:
  - 左サイドバー（写真、圧縮、設定）
  - 上部バー（検索、フィルタ、選択件数、監視状態）
  - 中央グリッド
  - 右インスペクタ（詳細、折りたたみ可能）
- テーマ: ダークを既定。既存アプリのWindows 11風の配色（背景 `#1a1a1a`、カード `#2d2d2d`、アクセント `#0078d4`）を踏襲する。
- キーボード:
  - `Ctrl/Cmd+F`: 検索
  - `Esc`: 選択解除 / 詳細を閉じる
  - `Enter`: 詳細を開く
  - `Space`: プレビュー
  - `Delete`: ゴミ箱へ移動（確認）
  - 矢印: グリッド移動
- 画像の右クリック、複数選択、ドラッグ選択はMVPに含める。ドラッグ＆ドロップ取り込みは余力があれば。
- 画像表示は`img` + `RenderImage`を`crates/ui/src/image_adapter.rs`に隔離する。GPUI本体のAPI変更はこのファイルだけで吸収する。
- gpui-kit のUI統合テスト（ヘッドレスウィンドウ）を活用し、主要画面の描画と操作をテストする。


### 7.8 トレイと自動起動

- Windows: `tray-icon` + `muda`（メニュー）。専用スレッドでWin32メッセージループを回す。
- Linux: `ksni`（StatusNotifierItem / D-Bus）。GTK依存を避け、AppImageに含めやすくする。トレイ非対応デスクトップではヘッドレスで動作し、UIから状態を確認できる。
- 自動起動: `auto-launch` クレート、またはOS別実装（Windowsレジストリ `HKCU\...\Run`、Linux `~/.config/autostart/*.desktop`）。
- 単一インスタンス: `single-instance` クレート。
- 二重起動時は既存デーモンにフォーカス/起動要求を送る。

### 8.1 gpui系UIライブラリの再評価（2026-10-21）

調査で判明した前提の訂正:

- crates.ioの`gpui`は**0.2.2（2025-10-22公開）**で、約1年間更新されていない。
- 現在のZed本体は**v1.25系（2026-10-20）**。`gpui-unofficial`はZedのリリースタグを追従して1.24.4 / 1.25.0-preを公開している。

| Zed git `ui`クレート | Zed公式 | ZedのUI部品 | あり | 常時更新 | `workspace`/`theme`/`settings`に密結合。単体利用は非現実的 |

**採用方針**:

- `gpui-kit = "=0.8.0"`を主軸にし、`Cargo.lock`をコミットする。`gpui-pre`は`gpui-kit`が厳密固定するため、アプリ側で直接バージョンを指定しない。
- アプリコードは`gpui_kit::*`と`gpui_kit::component::*`経由で統一する。公式`gpui`クレートを直接依存に追加しない（型非互換）。
- 写真グリッドは`gpui-kit`の`VirtualList` + `gpui::img`で自作する。DataTableは設定画面や圧縮履歴のような表形式に限定し、写真一覧には使わない。
- 画像のデコードと`RenderImage`への変換は`crates/ui/src/image_adapter.rs`に閉じ込め、GPUI APIの変更点を1箇所に集約する。
- `gpui-fast`（高速バックエンド）は既定では使わない。性能問題が出た場合のオプションとして`gpui-kit`のfeatureで検証する。
- **上流停滞時の方針**: `gpui-kit`はApache-2.0のため、必要な部品（VirtualList、Input、Dialog、DatePicker等）を`crates/ui/vendor/gpui-kit/`へコピーし、NOTICEを同梱して自リポジトリで保守する。全面的なフォークは行わない。
- **Phase 0ゲート**: 次の5点を両OSで検証する。
  1. 日本語IME（変換中のEnter、未確定文字列、ダイアログとのフォーカス移動）
  2. 10万件の仮想グリッド＋サムネイル同時表示（60fps、メモリ上限）
  3. 画像表示（PNG/JPEG/WebP、8K画像のプレビュー、ズーム）
  4. Linux Wayland（GNOME/KDE）での起動・フォント・クリップボード・画像
  5. `crates/ui`が`core`/`ipc`に依存されていないこと（逆依存のCIチェック）
- 5点が通れば案Aを継続。IMEまたはWaylandが致命的なら案B（`gpui-unofficial`＋自作）へ移行する。移行時も`core`/`ipc`/DBはそのまま使える。

## 10. テスト方針

### 10.1 単体テスト

- ログパーサ:
  - 実ログを匿名化したフィクスチャ。
  - ワールド参加/退出、プレイヤー参加/退出、ログ切替、未知行、壊れた行。
  - 同一秒の参加と退出、ユーザーIDなし、表示名の重複。
- ファイル名タイムスタンプ:
  - 正常系、ミリ秒なし、解像度違い、大文字拡張子、不正名。
- XMP:
  - 公開ワールド、プライベートワールド（メタデータなし）、XMPなし、壊れたXML。
- 紐付け:
  - セッション境界、前後3秒の推定、タイムゾーン、複数セッション、プレイヤーの入退室境界。
- 圧縮:
  - 各形式で生成物がデコードでき、寸法が正しい。
  - WebP/JXLのロスレス往復。
  - リサイズのアスペクト比。
  - 出力名衝突、ソース同一パス拒否、一時ファイルの後始末。
- DB:
  - マイグレーション、UNIQUE制約、WALでの読み書き、削除と復帰。

### 10.2 統合テスト

- 擬似VRChatディレクトリ（ログ、写真）を作り、デーモンを起動して以下を検証:
  - ログ追記 → セッション/プレイヤーがDBに入る。
  - 写真追加 → 文脈が紐付く。
  - 自動圧縮 → 出力ファイルと `derivatives` ができる。
  - 手動置換 → 元画像がゴミ箱に移動し、出力が残る（テストではゴミ箱をモック）。
  - 過去ログ再解析 → 既存写真が紐付く。
- IPC:
  - UI/デーモンのバージョン不一致、接続断、再起動、コマンドのタイムアウト。
- UI:
  - gpui-kitのヘッドレスウィンドウで、一覧表示、検索、詳細、圧縮ダイアログ、設定の主要操作。
  - 10万件のダミーデータでスクロールと検索の性能を計測。

### 10.3 手動検証

- 実際のVRChatセッションでログ形式を確認する（バージョン差異の確認）。
- XMP付き/なしの実写真で表示を確認する。
- Windows 10/11、Ubuntu 24.04、Steam Deck（Proton）で起動・トレイ・自動起動を確認する。
- 8K写真、AVIF/JXL生成物、日本語ファイル名、長いパス、OneDrive配下のパスを確認する。

### 10.4 CI

- GitHub Actions:
  - `cargo fmt --check`
  - `cargo clippy --all-targets -- -D warnings`
  - `cargo test --workspace`
  - Windows / Ubuntuのビルド
- Linuxビルド依存: `libxkbcommon-dev`、`libwayland-dev`、`libvulkan-dev`、`cmake`、`ninja-build`、`clang`。
- リリースビルドはタグ時に実行。成果物はGitHub Releasesに添付。

## 11. リスクと対策

| # | リスク | 影響 | 対策 |
|---|---|---|---|
| 1 | `gpui-kit`が`gpui-pre`スナップショットに厳密固定され、公式gpuiと型互換がない | 将来の乗り換えコスト | UI層を隔離。Phase 0ゲート。上流停滞時はApache-2.0の範囲で必要部品をvendoring。最悪は`gpui-unofficial`＋自作へ移行 |
| 2 | `gpui-kit` / `gpui-pre`のAPI変更が速い（週次リリース） | ビルド破壊 | `gpui-kit = "=0.8.0"`、`Cargo.lock`コミット。アップグレードは専用ブランチとCIで検証。直接`gpui`クレートを依存に追加しない |
| 3 | crates.ioの`gpui` 0.2.2が1年間更新されず、最新Zedと乖離している | 古いAPIを選ぶ事故 | 技術選定時に公開日とZed本体のバージョンを確認する。必要なら`gpui-unofficial`（Zedタグ追従）を比較対象にする |
| 4 | VRChatのログ形式が変わる | 文脈が取れない | パーサをバージョン管理。未解析行を診断表示。フィクスチャを追加。生ログは保存しない方針のため、必要時に一時的なデバッグ保存をオプトインで用意 |
| 5 | VRChatログが24時間で消える | 初回の過去復元が限定的 | デーモンの自動起動を既定ON。解析済みイベントをDBに永続化。UIで制約を明示 |
| 6 | ワールド表示名が取れない（プライベートワールド、XMPなし） | 検索・表示がIDだけになる | ワールドIDを表示。手動エイリアス。将来の任意API連携（要認証） |
| 7 | トレイがLinuxデスクトップによって動かない | 常駐操作ができない | `ksni` を使用。非対応環境ではヘッドレス動作＋UIから制御。ログに理由を出す |
| 8 | 10万枚のサムネイルでディスク/CPUを圧迫 | 動作が重い | 遅延生成、可視範囲優先、2GB LRU、WebP、ワーカー数制限 |
| 9 | 置換時のデータ消失 | ユーザー写真を失う | 一時ファイル＋デコード検証＋ゴミ箱移動。置換は手動時のみ。失敗時は元画像を残す |
| 10 | AVIFの「ロスレス」が現行実装では真のロスレスでない | 画質劣化 | 移植時に `ravif` のロスレス設定へ修正。UI表記も修正 |
| 11 | JPEG XLのαが落ちる | 透過写真の劣化 | UIで警告。α対応が必要になったらエンコーダ側を再検討 |
| 12 | SQLiteの同時書き込み競合 | 一時的な失敗 | WAL、busy_timeout、書き込みをデーモンに集約、UIは短いトランザクション |
| 13 | タイムゾーン/DSTで紐付けがずれる | 誤った文脈 | ローカル時刻で比較。UTCオフセット保存。手動再紐付け |
| 14 | LinuxのGPU/ドライバ依存（Vulkan） | 起動しない環境がある | 要件を明記。起動時診断。ソフトウェアレンダリングは対象外 |
| 15 | 依存クレートのライセンス/ビルド（libjxl vendored） | 配布できない | CIでライセンス確認。WindowsはCMake/Ninjaを同梱したビルド手順。AppImageに静的リンク |
| 16 | 写真ファイルの外部変更（移動/削除） | リンク切れ | `missing` 状態。再スキャンで復帰。DBから勝手に消さない |

## 付録A: 主要な判断の記録

| 判断 | 理由 |
|---|---|
| 公式WebSocketを使わない | ワールド/同接者を配信しないため、写真の文脈取得に使えない。認証管理のコストだけ増える |
| ログ監視を主とする | ワールド遷移とプレイヤー入退室をローカルで取得できる唯一の実用的な手段 |
| XMPを補完に使う | ワールド表示名と撮影者の取得に有効。ただしプライベートワールドと他プレイヤーは取れない |
| 生ログを保存しない | 個人情報と容量のリスクを避ける。解析済みイベントで再紐付けは可能 |
| 参照方式を既定とする | ユーザーの既存ファイルを動かさない。取り込みは任意 |
| 自動圧縮は元画像保持固定 | 自動処理で不可逆な変更をしない。置換は手動時のみ |
| 削除はゴミ箱のみ | 事故防止。完全削除はOSに任せる |
| gpui-kitを採用 | 10万件の仮想リスト/テーブル、フォーム、i18n、AccessKit、UIテストを備え、写真管理に必要な部品が多い。GPUI本体はZed 2026-10-10スナップショットで、crates.ioの`gpui` 0.2.2より新しい |
| gpui-kitのバージョンを厳密固定 | 週次リリースでGPUIスナップショットが変わるため、`=0.8.0`と`Cargo.lock`で再現性を確保する |
| 上流停滞時はvendoring | gpui-kitはApache-2.0。必要部品だけコピーして保守すれば、UI全体の書き直しを避けられる |
| Phase 0でgpui-kitを実機検証 | IME、10万件グリッド、画像、Wayland、UI層の独立性の5点が通らなければ案Bへ移行する |
| 別プロセス構成 | ログ監視をUIの起動状態から独立させる。UIが落ちても記録を継続 |
| 単一バイナリではなく2バイナリ | WindowsのGUIサブシステム、トレイ、自動起動の扱いが明確になる |

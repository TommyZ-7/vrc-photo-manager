# UI仕様

2026-10のガラス背景リボンUI（[#118](https://github.com/TommyZ-7/vrc-photo-manager/issues/118)）後の実装を記述する。写真を主役にした構成で、ナビゲーションと状態表示は画面の端に置く。

## 1. 技術

- `gpui-kit = "=0.8.0"`（`gpui-component` を含む）。
- GPUI本体は `gpui-kit` が固定する `gpui-pre` 0.3.9。アプリから直接 `gpui` クレートを追加しない。
- 日本語フォントは `crates/ui/assets/NotoSansJP.ttf` をバンドルし、起動時に登録する。
- `crates/ui/src/main.rs` はブートストラップだけを持ち、`App` は `app.rs`、状態型は `state/`、画面と共通部品は `ui/` に分割する（[architecture.md](architecture.md) §3）。
- コンポーネントテーマは `gpui_component::init` がライト固定のため、初期化直後に `Theme::change(ThemeMode::Dark, None, cx)` でダークへ切り替える。ボタン等を個別に色指定しない。
- `gpui-component::TitleBar` と `WindowOptions` を使い、Linuxでは `WindowDecorations::Client` を要求する。拒否された場合はサーバー側装飾にフォールバックし、`TitleBar` はウィンドウ操作ボタンを描画しない。アプリ内のタブ・状態行は残す。
- ウィンドウ背景は `WindowBackgroundAppearance::Blurred` を要求する。blurが使えない環境でも、アンビエント層と不透明カードで読めることを前提にする。
- ウィンドウの最小サイズは 1080×700、既定は 1280×820。`--window-size WxH` で変更できる。

## 2. シェル

```text
OSウィンドウ（背景ブラー要求）
└─ アンビエント層（暗いグラデーション＋色付きグロー）
   └─ 14pxパディング・14pxギャップ
      ├─ サイドバーカード（238 / 78）
      └─ メイン列
         ├─ ヘッダーカード
         │  ├─ タイトルバー 46px（アプリ名・画面名・3タブ・状態・ウィンドウ操作）
         │  └─ リボン 68px（高さ760px以下は62px）
         └─ コンテンツ（外側カードなし。画面ごとの内部カード）
```

- **ガラスはウィンドウ背景だけ**。サイドバー、ヘッダー、コンテンツ、内部カード、ビューア、モーダルは不透明なパネル色（`PANEL_*`）で描く。要素単位のブラーや半透明カードは使わない。
- アンビエント層は暗いグラデーションと3つの低不透明度グローで構成する。blur非対応でも背景のコントラストは保つ。壁紙が見えること自体は要件にしない。
- ヘッダーカードは角丸22px。タイトルバーとリボンを1枚のカードにまとめる。
- コンテンツ領域に外側カードを置かず、画面ごとのギャラリー/フィルター/設定カードだけを描く。画面見出し（72px）は全画面で削除した。現在画面名はタイトルバーに出す。
- 角丸はウィンドウ内カード22px、内部カード17px、写真カード13px、ボタン7-8px、ピル999px。カードは不透明なパネル色・1px境界・上辺インセットハイライト・弱い影で分離する。

### 2.1 タイトルバー

左から、アプリグリフ（22px）、`VRC Photo Manager`（11px、muted）、区切り、現在画面名（11.5px）、リボンタブ（ホーム/写真/圧縮、27pxピル）。右寄せにデーモン状態ピル、最終同期、リボン折りたたみ、通知ベル、`TitleBar` 標準のウィンドウ操作を置く。

- タブのアクティブは半透明の青面＋境界＋上辺ハイライト。下線バーは使わない。
- 画面切替時、`Screen::Compression` なら圧縮タブ、それ以外はホームタブを既定にする。手動で選んだタブは同じ画面にいる間維持する。
- リボンが折りたたまれているときにタブを押すと展開する。
- 折りたたみ状態は `ui_ribbon_collapsed` として保存し、起動時に復元する。
- 最終同期はハートビートが新しければ「N秒前」、古くIPC接続中なら「IPC」、どちらもなければ「停止」、デモ時は「デモ」と表示する。幅1180px以下では同期表示を省略する。
- 通知ベルは未読メッセージがあるときアンバーのドットを出す。トーストは新設しない。
- ウィンドウ操作は `TitleBar` の標準コントロールを使い、独自の偽ボタンは描かない。Linuxでクライアント装飾が拒否された場合はコントロールを描画しない。

### 2.2 リボン

- 高さ68px。ウィンドウの内容高さが760px以下なら62px（ボタン44→38px、小ボタン21→19px、グループラベル10→9px）。
- **ホーム**: コピー取込 / 移動取込、再読込、フォルダを開く、索引を再構築、詳細パネル（写真画面のみ）、現在の状態。
- **写真**: すべて選択 / 選択解除 / お気に入り、全画面 / タグ / メモ、ゴミ箱へ / 圧縮。写真を選んでいないコマンドは無効化する。
- **圧縮**: 手動圧縮 / 待機を圧縮 / 失敗を再試行、キュー / 状態（ダッシュボードへ）、自動適用の現在値。
- 設定固有のコマンド（ガラス強度・モーション・テーマ・ログ・更新・バージョン・ショートカット）はリボンから外し、設定画面に置く。
- ライブラリのインライン検索とリスト表示は対象外。検索は検索画面 / `Ctrl/Cmd+K` を使う。
- リボンの右端は「現在の状態」領域。選択枚数・総枚数・容量、または `App.message` を出す。幅1180px以下では省略し、メッセージはコンテンツ上の細い行に出す。
- メッセージ行はリボンが折りたたまれているとき、写真タブ表示中、幅1180px以下でも見えるようにする。閉じるボタンで消せる。トーストや自動消去は使わない。

### 2.3 サイドバー

- 展開時 238 px、最小化時 78 px。幅は440 msでアニメーションする。
- ナビゲーションは5項目。写真 `GalleryVerticalEnd` / 検索 `Search` / 圧縮 `Minimize` / ダッシュボード `LayoutDashboard` / 設定 `Settings`。
- 写真にはライブラリ枚数、圧縮には未完了（waiting / pending / processing）のジョブ数（0件なら非表示）を出す。検索・ダッシュボード・設定は件数なし。ダッシュボードは下部のステータスドットで状態を示す。
- ライブラリカードの直上に「進行状況」カードを置く。展開時のみ表示し、最小化時と内容高さ760px以下では隠す。「圧縮 / 取り込み / スキャン」の3タブで表示を切り替え、選択タブはセッション内だけ保持する。非表示のタブに活動があるときは、タブ右上の4 pxドットで知らせる（赤=失敗、黄=未実行/未処理、青=実行中）。タブは自動で切り替えない。
  - 圧縮: 未実行・実行中・失敗の件数を出す。未実行があるときは「未実行を開始」で全待機ジョブを解放し、元画像置換ポリシーでは確認ダイアログを出す。失敗があるときは「再試行」で上限内の失敗を再実行する。どちらもないときは「キューを開く」でダッシュボードへ移動する。
  - 取り込み: 実行中は処理済み/総数と失敗数を出す。完了後は直近の取り込み結果（完了・失敗・部分移動・未処理・連番・スキャン失敗）を出し、「結果を見る」で写真画面の取り込み結果パネルへ移動する。
  - スキャン: 索引中は進捗%とフォルダ/索引の詳細、不在時は待機中・一時停止中・停止中を出す。待機中は「再スキャン」、それ以外は「ダッシュボード」を出す。
- 下部にライブラリ枚数と総容量のカード、デーモン状態（監視中 / 一時停止中 / デーモン停止）、バージョン（デモ時は `DEMO DATA`）を表示する。
- 右端にまたがる形のフローティングトグルで展開/最小化する。ツールチップに操作名と `Ctrl+B` を表示する。
- `Ctrl/Cmd+B` で切り替え。状態は `ui_sidebar_collapsed` としてDBに保存し、再起動後も維持する。
- 最小化時はラベル、件数、進行状況カード、ストレージカード、状態テキストを隠し、アイコンを中央揃えにする。ホバーすると右側に画面名のツールチップを出す。
- 選択中の項目は `ACCENT_SOFT` の背景と2 pxのアクセントバーで示す。

全画面共通:

- 圧縮の失敗ジョブ、デーモンの処理エラー、取り込み失敗のいずれかがある間、内容の上にグローバル通知バーを積む。1行1件で、赤いドット、件数入りの短文、「ダッシュボードを開く」「写真を開く」のいずれかを出す。
- 通知バーは閉じられない。対象の失敗が解消するか、取り込み結果パネルを閉じると消える。詳細な理由は移動先の画面に置き、バーでは省略する。

### 2.4 写真

ページ見出しは置かない。コンテンツはギャラリーカードとインスペクタカードの2枚。

- ギャラリーカードのヘッダーは42 px。左に現在月（`YYYY年M月`）と `N枚 / 総枚数`、右に「フィルター」ボタンと「並び: 新しい順」を出す。フィルターボタンは既存の4チップ（ワールド / プレイヤー / 日時 / タグ）をインラインで開閉する。フィルタリング処理は追加しない（外観のみ）。
- インライン検索欄は置かない。検索は検索画面 / `Ctrl/Cmd+K` を使う。
- 「再読込」「フォルダを開く」「索引を再構築」「詳細パネル」はリボンのホームタブ（詳細パネルは写真画面のみ）。再読込は索引とページキャッシュを作り直し、表示中の先頭写真をアンカーとして維持する。索引・ページの読込に失敗したときはギャラリーを消さず、赤いエラー行と再試行ボタンを出す。
- 「コピー取込」「移動取込」はリボンのホームタブ。取り込みモーダルを開き、ファイルまたはフォルダを選び、設定で固定された取り込み先を確認して開始する。フォルダは再帰的に走査し、`compressed/`、シンボリックリンク、取り込み先自身のサブツリーを除外する。
- 取り込み中はモーダルに処理済み/総数・取込・スキップ・失敗と、最後に処理したファイル名を表示する。新規取り込みでは選択中の取り込み元も表示する。キャンセルは次のファイル手前で止まり、モーダルは結果が出るまで残る。モーダルはフォーカストラップでキーボード操作を閉じ込める。
- 取り込み後はギャラリーカードの上に「取り込み結果」パネルを出す。タイトルにモード（コピー / 移動）と取り込み先、バッジに取込・スキップ・失敗・部分移動・スキャン失敗・連番・未処理の件数を表示する。
  - 「失敗したファイル」は元パスと理由を並べる。再試行可能な失敗があるときだけ「失敗分を再試行」を出し、同じ取り込み先・モードでモーダルを開いてバックグラウンド再実行する。再試行もキャンセルできる。
  - 「連番を付けたファイル」は名前衝突で連番された元パス → 保存先を並べる。高さ150 pxを超える分はスクロールする。
  - 「移動元を削除できなかったファイル」は部分移動の警告で、移動元・移動先・削除失敗の理由を出す。移動先にはファイルがあり、取り込み済みとして数える。部分移動は再試行しない。
  - 未処理が残るときは「残り N 件を再開」を出し、残りだけを同じ経路で再実行する。
  - 「スキャンできなかったファイル」と、取り込み先の索引・紐付けに失敗したときのハードエラーも同じパネルに出す。
  - パネルは「閉じる」で消すまで残る。閉じると再開情報は失われる。失敗がある間はグローバル通知バーにも件数が出る。
- フィルターボタンを開くと、ワールド / プレイヤー / 日時 / タグの4チップ（表示のみ。動作は未実装）をギャラリーヘッダー下に並べる。並びは右端の「並び: 新しい順」で、新しいソート処理は追加しない。
- ギャラリーは `uniform_list` による仮想スクロール。100k件でも行は全件分あり、表示範囲の写真だけを256枚ページで遅延取得する。カードは3:2画像＋タイトル/日時/サイズ。最小幅190 px、列間9 px、選択・お気に入り・圧縮状態のバッジを維持する。
- サムネイルは表示中のカードだけを非同期デコードし、192件のLRUで保持する。同時デコードは最大4件。UIスレッドではデコードしない。
- 1200 pxプレビューも非同期でデコードする。選択ハイライトは即時に描画し、プレビューは背景デコードの完了後に差し替える。同時デコードは1件で、連続して切り替えたときは最後に選んだ写真だけを取得する。結果は `<data_dir>/previews/<photo_id>-<variant>.webp` にWebP（品質85）でキャッシュし、元画像のmtimeと表示derivative IDで鮮度を判定する。キャッシュは2048ファイルを上限とし、32回目の書込ごとに古い順へ1536まで削減する。UIスレッドではデコードしない。
- 右端に年レールを重ねる（[2.4.1](#241-年レール)）。
- クリックで単一選択、`Ctrl/Cmd+クリック` で選択の追加・解除、`Shift+クリック` で直前に選んだ写真からの範囲選択。これはライブラリと検索の両方で使える。
- 2件以上選択するとギャラリー上に「N件選択中」「選択解除」「N件を圧縮」のバーを出す。選択解除はその場で全選択を外す。
- 選択中のカードは左上にチェックバッジを出す。主選択（インスペクタに表示する写真）は `BLUE`、追加選択は淡いブルーのリング。
- ライブラリと検索を切り替えたとき、検索を実行・クリアしたときは選択を解除する。圧縮設定／設定画面へ移動したときは選択を保持する。
- 列数は既定（Medium）で、サイドバーとインスペクタが開いた状態では1280×820 / 1440×900が3列、1080×700が2列。カードサイズ設定（小/中/大/特大）は列数上限と最大幅で密度を変える。インスペクタを隠すと列数が増えることがある。ウィンドウのリサイズ、サイドバー/インスペクタの開閉で行高・列数が変わっても、表示中の先頭写真をアンカーとして維持する。
- カードは角丸13 px。選択中は2 pxの `BLUE` リングと淡いグロー、ホバー時は180 msで4 px浮く。
- カードのバッジは圧縮済み / 未圧縮のドットとラベル、お気に入りのアンバードット。タイトルはワールド名、下段に日付とサイズ。
- 初回表示は600 msのフェード+14 px移動。40 ms間隔のスタッガー（最大8段、先頭24枚まで）。スクロールで行が再マウントされても再生しない。
- 右インスペクタは幅298 / 276 / 254 px（1440 / 1280 / 1080）の列に、幅282 / 260 / 238 px・角丸17 pxの不透明カードを16 pxマージンで置く。
- インスペクタ背景は選択写真のサムネイル（256 px）の平均色。サムネイルを拡大して45%の不透明度で敷き、暗いグラデーションのスクリムを重ねる。カード自体は不透明で、背景のガラスを透かさない。
- プレビューの高さは168 px（内容高さ760px以下では118 px）。幅は列幅に追従するため、表示比率は16:10に固定されない（設計書§11.1の16:10指定と固定高さのトレードオフ）。写真を切り替えると、プレビューと背景色を260 msでクロスフェードする。選択直後の1回だけ再生し、インスペクタの開閉や画面復帰では再生しない。デコード中は256 pxサムネイルを敷き、インスペクタには「プレビューを読み込み中…」を出す。ビューアはサムネイルが無い場合だけ同じラベルを出す。
- 内容はタイトル、日時、バッジ、メタデータ、撮影時プレイヤー、タグ、下部に「全画面表示」「圧縮」。複数選択中は「圧縮」が「N件を圧縮」になり、選択した全件を対象にする。
- リボンの写真タブ「詳細パネル」または `Ctrl/Cmd+I` で表示/非表示。列幅は300 msでアニメーションし、状態は `ui_inspector_collapsed` として保存する。
- 空のときは案内カードを表示する。一覧は全件を仮想グリッドで表示し、件数上限はない。

### 2.4.1 年レール

- グリッド右端の20 pxガターにオーバーレイとして置く。リストの上に描画し、レール内のクリック・ホバーは下のカードへ通さず、ホイールスクロールだけを通す。
- 年ラベルは新しい年から順に、その年より新しい写真の累計枚数に比例した位置へ置く。写真が多い年ほど縦の領域が広くなる。
- 現在表示中の先頭写真の月を `YYYY年M月` のピルで表示する。ピルは80×18 px、角丸9 px、`PANEL_2`（94%不透明）背景に `TEXT` 色の文字で、レールのトラック上に重ね、スクロールに追従する。
- 年ラベルをクリックするとその年の先頭写真へ移動する。ラベルから8 px以内はその年へのジャンプとして扱う。
- レール上をドラッグすると、ポインタ位置に対応する写真位置へ連続的に移動する。ドラッグはレール外へポインタが出ても続く。
- ジャンプ先は `grid_row = photo_row / columns` で行へ変換し、`-(grid_row * row_height)` を GPUI の `max_offset()`（非負のスクロール可能量）で `-max_offset..0` にクランプする。`row_height` は3:2カードの列幅から算出し、リサイズ・カードサイズ変更後も同じ helper を使う。
- ラベルが16 px未満に近づく場合は、先頭の年から順に16 px以上離れたラベルだけを描く。ドットは全年に描く。
- 写真が0枚のときはレールを表示しない。

### 2.5 フルスクリーンビューア

独立した写真詳細画面は廃止し、このビューアの詳細パネルへ統合した。

- シェル全体を覆う全画面オーバーレイ。背景は暗色に選択写真の平均色を薄く重ねる。表示時は240 msでフェードインする。
- 上部バーは高さ56 px。左から「閉じる Esc」「前へ」「次へ」、ファイル名、「詳細」/「詳細を閉じる」。
- 画像は1200 pxのプレビューを `Contain` で中央に表示する。画像そのもののクリックでは閉じず、暗いレターボックスのクリックで閉じる。
- 詳細パネルは幅380 px（閉時は0）。初回は閉じた状態で開き、以降の開閉状態はセッション中だけ記憶する。幅は300 msでアニメーションし、画像領域が追従する。
- 詳細パネル内は角丸17 pxの不透明カード（`PANEL_CARD`→`PANEL_DEEP`）とし、背景の画像を透かさない。パネルはスクロール可能で、`detail_body` を共有する。内容はお気に入り、タグ追加・削除、圧縮履歴、メモの表示・編集、圧縮、ゴミ箱（2段階確認）。
- タグチップの `×` でタグを削除できる。削除は残りのタグを `set_photo_tags` で保存し、詳細とインスペクタへ即時反映する。
- メモは「編集」で複数行入力を開き、「保存」「キャンセル」で閉じる。空・空白のみは `NULL` として保存し、「メモはまだありません」に戻る。編集中の `Esc` はビューアを閉じず編集だけをキャンセルする。
- 有効な検索にタグ条件がある場合、タグ編集後に同じ条件を非同期で再検索し、先頭写真のスクロール位置を維持する。
- お気に入りとタグの編集ではビューアを閉じない。圧縮は完了メッセージを見せるため開いたまま。ゴミ箱移動に成功したときだけ閉じる。
- 起動経路は、写真カードのダブルクリック、グリッドフォーカス中の `Space` / `Enter`、インスペクタの「全画面表示」。
- 移動元は現在の写真一覧、検索から開いた場合は検索結果。端では前へ/次へが止まる（ラップしない）。移動に合わせて背後の一覧選択も更新する。
- `Left` / `Right` は上部バーにフォーカスがあるときだけ前後移動。詳細パネルの入力中は移動しない。
- 開くと「閉じる」にフォーカスする。`Tab` / `Shift+Tab` は閉じる、前へ、次へ、詳細トグル、パネル展開時はお気に入り、タグ入力、追加、メモ編集（編集中は入力欄・保存・キャンセル）、圧縮、ゴミ箱の順に循環する。フォーカスはビューア内に閉じ込め、背後のシェルは操作できない。グローバルの `Ctrl/Cmd+B` / `K` / `I` と `OpenQuickLook` も無視する。取り込みモーダルと手動圧縮ダイアログを開いている間も同じグローバル操作を無効にする。
- 閉じると開く前にフォーカスしていた要素（通常は写真グリッド）へ戻す。

### 2.6 圧縮設定

- ページ見出しは置かない。左のプロファイルカードと右のエディタカードの2枚。
- プロファイル追加（`＋ 追加`）は左カードの42 pxヘッダーに置く。手動圧縮はリボンの圧縮タブ。手動圧縮はダイアログを開き、対象・プロファイル・出力先・元画像の扱いを確認してから実行する。
- 左に幅280 pxのプロファイルカード一覧（選択、名前、形式、品質/ロスレス、自動/手動バッジ、↑↓）。先頭の ↑ と末尾の ↓ は無効。並び順は保存され、再起動後も維持する。カードは内容領域の高さいっぱいに伸び、一覧は内部スクロールする。
- 右の編集画面は「形式と画質」「リサイズ」「出力」に分ける。形式、品質、ロスレス、リサイズ（有効/無効、解像度、方法、アスペクト比）、サフィックスを編集し、出力先は「フォルダを選択」で変更できる。「既定に戻す」で元画像の隣の `compressed/` に戻す。「複製」と「削除」を置く。
- リサイズ方法は「大きい場合のみ」と「毎回」から選ぶ。既定は「大きい場合のみ」で、指定解像度内に収まる画像は拡大しない。
- サフィックスはテキスト入力で即時保存する。空欄可。ファイル名に使用できない文字は `_` に置換する。
- 自動適用スイッチには「自動圧縮に使う」「新規写真にこのプロファイルを適用します」のラベルと説明を付ける。
- ロスレスはプロファイルごとに切り替えられる。WebP / JPEG XL はON/OFF、AVIFは近似ロスレス、JPEGは非対応として無効化する。ロスレスON中は品質の増減を無効にし、「ロスレスでは品質指定を使用しません」と表示する。形式をJPEGへ変えると `lossless` はOFFへ戻る。
- 「複製」は「〈名前〉のコピー」を元の直後に追加する（衝突時は連番）。複製は自動適用OFFで作る。
- 「削除」は AlertDialog で確認する。`waiting` / `pending` / `processing` のジョブがある間は削除をブロックして理由を表示する。最後の1件も削除できない。キャンセルでは何も消えない。
- 統計は総圧縮数、写真数、圧縮後合計。キューはダッシュボードへ移動した。
- 自動圧縮の適用順はプロファイル一覧の並び順に従う。
- 手動圧縮ダイアログは、対象枚数、登録プロファイルのラジオ選択、出力先（指定フォルダ / プロファイル指定フォルダ / クリップボード）、元画像（保持 / ゴミ箱へ移動）を表示する。指定フォルダは「フォルダを選択」で決める。クリップボードは1枚選択時だけ有効で、複数選択時は理由付きで無効化する。実行ボタンは出力先が未選択なら無効。

### 2.7 検索

- ページ見出しは置かない。左のフィルターカードと右の結果カードの2枚。フィルターカードは幅290 pxで内容領域の高さいっぱいに伸び、必要なら内部スクロールする。ワールド / プレイヤー / タグのテキスト入力、日時プリセット（今日 / 7日 / 30日 / すべて）、お気に入りスイッチ、検索 / クリアを置く。
- 結果カードは42 pxヘッダー（件数、`検索中…`、`message`、選択バー、`並び: 新しい順`）と仮想グリッド。カードはライブラリと同じ3:2画像・最小幅190 px・9 pxギャップで、既定では1280×820 / 1440×900が3列、1080×700が2列。結果は件数上限なしで全件スクロールできる。
- 検索画面にはインスペクタ列がないため、検索の利用可能幅はフィルターカード・シェルのパディング・ギャップ・年レールガターを差し引いて計算する。カードサイズ設定はライブラリと同じく密度に反映する。
- 検索結果にも年レールを表示する。挙動は写真画面と同じ（同じ行高 helper を使う）。
- 複数選択と一括圧縮はライブラリと同じ。`Ctrl/Cmd+クリック`、`Shift+クリック` が使え、2件以上で選択バーを出す。検索の実行・クリアで選択を解除する。
- カードのダブルクリックでフルスクリーンビューアを開ける。
- `Ctrl/Cmd+K` で検索画面へ移動し、ワールド入力にフォーカスする。

### 2.8 ダッシュボード

ページ見出しは置かない。上段に統計4枚、下段左に共有圧縮キュー、右列にデーモン・現在のセッション・監視パス・ログを並べる。キューと右列は内容領域の高さいっぱいに伸び、内部スクロールする。再読込はリボンのホームタブを使い、デーモンカードの操作はそのまま残す。

- 稼働状態は `daemon_heartbeat` が20秒以内、またはIPC購読が接続中かで判定する。長時間スキャン中にハートビートが古くなっても停止扱いにしない。
- 統計カード4枚（写真、未完了ジョブ、未実行、デーモン）、共有圧縮キュー、デーモンカード、現在のセッション、監視パス、ログを表示する。
- 共有圧縮キューは全プロファイルのジョブを1つの一覧に表示する。各行に状態、写真ID、プロファイル名、進捗を出す。
- キュー上部に「未完了 N」「未実行 N」「失敗 N」のバッジを出し、`waiting` があるときは現在の「自動: 元画像を保持 / 置換」と「待機をすべて圧縮」を表示する。このボタンは全プロファイルの `waiting` を `pending` に戻し、デーモンを起こす。`replace` のときは実行前に確認ダイアログを出す。
- 待機ジョブは最大20件、待機以外の最近のジョブは最大6件表示する。失敗ジョブは写真名、プロファイル名、失敗理由（折り返し表示）、`再試行 n/3` を出す。`retry_count < 3` なら「再試行」ボタンを出す。
- キューの「失敗をすべて再試行」は、読み込んだ最新100件の失敗に再試行可能なものが1件でもあるときに出す。上限到達時は「再試行の上限（3回）に達しました」と表示し、ボタンを出さない。
- 失敗が100件を超える場合は最新100件だけを表示する旨を出す。「失敗をすべて再試行」は表示範囲に関係なく、DB上の再試行可能な全件（100件より古いものも含む）を対象にする。
- 現在のセッションカードにワールド、インスタンス、同接者を表示する。
- デーモンカード: 最終同期、IPC接続状態とエラー、監視の一時停止状態、スキャン進捗（フォルダ番号・索引件数・バー）、「再スキャン」「監視を一時停止/再開」「デーモンを終了」を表示する。再スキャンはDBに積んでIPCで起こす。一時停止/再開と終了はIPC接続中のみ有効で、終了は2回押し確認。停止中は「停止中」バッジを表示し、一時停止/再開・終了ボタンを無効化する。
- スキャン進捗イベントはwalking（検索中）とindexing（索引中）を区別し、フォルダが複数ある場合は「フォルダ n/N」を出す。
- `daemon_errors` が空でないときは「処理エラー」カードを出す。操作（写真スキャン / ログ解析 / 写真の紐付け）のラベル、赤いメッセージ、折り返し表示のモノスペース詳細、検出回数、発生時刻（`MM/DD HH:MM`、解析できなければ生文字列）を並べる。「再試行」は操作に対応する `rescan` / `relog` / `relink` を `daemon_commands` に積み、IPC接続中なら `wake_commands` で即時実行する。デーモン停止中はコマンドがキューに残り、起動後に実行される旨を表示する。
- 「ログ」カードにログフォルダ、`vrc-photo-manager.log` と `vrc-photo-daemon.log` の2ファイル名、「ログフォルダを開く」を出す。データディレクトリを特定できない場合は「ログフォルダを特定できません」「ファイルへのログ出力は利用できません」と表示する。データディレクトリは解決できるがログファイルを開けない場合、カードは保存先とファイル名を表示したまま、ログはstderrのみになる。
- VRChat本体が出力ログを24時間で削除することをアンバーの注意書きで明示する。

### 2.9 設定

ページ見出しは置かない。左に220 pxのカテゴリナビカード（ライブラリ / 表示 / 起動と圧縮 / アップデート / ログ）、右に設定カードを並べる。ナビの行は右列の該当セクションへスクロールし、スクロール位置に応じてアクティブ行が変わる。右列は内部スクロールし、末尾に「設定を再読込」を置く。

- 「ライブラリ」: 写真フォルダ、ログフォルダ、取り込み先。「パスを保存」で設定を書き込み、写真フォルダ・ログフォルダ・取り込み先のいずれかが変わったときは `rescan` を要求する。IPC接続中なら `wake_commands` で即時実行し、停止中なら起動後に実行される。デーモンは要求を受けると設定を再読込して監視を張り直す。要求の書き込みに失敗した場合は、デーモン再起動で反映される旨を表示する。
- 「起動と圧縮」: 自動起動、トレイ常駐、自動圧縮、新規写真をすぐに圧縮、自動圧縮後に元画像を保持、アニメーションを減らす、の各スイッチ。スイッチは即時DB保存。
- 自動圧縮がONのときだけ「新規写真をすぐに圧縮」を表示する。OFFにすると新規写真は `waiting` に入り、ダッシュボードの「待機をすべて圧縮」で実行する。
- 「自動圧縮後に元画像を保持」がOFFで、自動圧縮がONのときは「自動圧縮で圧縮に成功すると元画像をOSゴミ箱へ移動します」という警告カードを表示する。手動圧縮の元画像は実行時にダイアログで選ぶため、この設定の対象外。
- 圧縮関連の設定は、実行中のデーモンが2秒ごと、および差分索引の直前に再読込する。設定変更のためにデーモンを再起動する必要はない。
- 自動起動はデーモンが10秒間隔で設定を拾ってOSへ反映する。
- 「ログ」カード: ダッシュボードと同じ内容を表示し、「ログフォルダを開く」からOSのファイラーを開ける。
- 「設定を再読込」と、言語・サムネイルキャッシュ容量の表示。

## 4. モーションとアクセシビリティ

- イージングは `cubic-bezier(0.22, 0.8, 0.24, 1)` 相当。依存追加なしのソルバーで実装する。
- 主な時間: サイドバー幅 440 ms、ラベル 320 ms、インジケータ 220 ms、画面切替 220 ms、色 / ツールチップ 160 ms、インスペクタ / ビューア詳細パネル 300 ms、ビューア全体 240 ms、ビューア画像モーフ 340 ms、写真切替 220 ms、カード出現 600 ms + 40 ms スタッガー、ホバー 180 ms、プレビュー / 色クロスフェード 260 ms。
- サイドバーの選択ピルと青い縦バーは 1 つの共有要素。タブ移動では縦にスライドし、折りたたみではバーが幅の変化に追従する。アイコン・ラベル・件数も選択状態に合わせてクロスフェードする。
- 画面切替はサイドバー順に応じた左右 14 px のスライド＋フェード。グローバル通知バーは動かさない。
- 写真ビューアはカード画像（またはインスペクタプレビュー）の画面座標からビューア画像枠へ、サムネイル／プレビューをクロスフェードさせながら移動する。閉じる時は逆方向に戻り、元のカードが見つからない場合はフェードで閉じる。開くモーフ中に Esc した場合は、その時点の位置から戻る。
- ビューアの前後移動は方向付きクロスフェード。アスペクト比が変わる場合は画像枠の幅・高さを 220 ms で補間し、詳細パネル開閉時はパネル幅と画像枠を 300 ms で同期させる。
- ビューアの上部バー、詳細本文、手動圧縮ダイアログ、取り込みモーダル、取込レポート、通知バー、メッセージ行、複数選択バー、圧縮プロファイル選択にも短い進入アニメーションを付ける。
- 表現は不透明度、幅、高さ、小さな位置オフセットのみ。任意要素への `scale` / `rotate` は使わない。
- 60 fps 上限（`with_max_fps(60.0)`）を指定し、アニメーション中に画像デコードやDBクエリを起こさない。
- 設定の「アニメーションを減らす」で低減できる。値は `ui_reduce_motion` として保存し、`cx.set_reduce_motion` に反映する。`with_animation` は低減時に最終状態を描画し、ビューアモーフのカスタムタイマーも開始しない。OS設定の自動検出はしない。

## 5. 自動更新（3秒ポーリング）

- `App::start_auto_refresh` が3秒間隔で以下を更新する。
  - デーモンハートビート、現在のセッション、同接者
  - 統計、共有圧縮キュー（待機・失敗一覧と件数を含む）、デーモンの処理エラー
  - 選択中写真のタグ・プレイヤー・圧縮履歴
- 写真枚数が変わった場合だけ索引を再構築する。3秒tickで変化を検出し、その枚数が静定するquiet-periodを待ってから1回だけ再構築する（取り込みが続く間は待機を延長する）。表示中の先頭写真をアンカーとしてスクロール位置を維持し、サムネイルはID単位で保持する。3秒ごとの再デコードは行わない。
- タイトルバーの同期表示は、ハートビートが新しければ「N秒前」、古いがIPC接続中なら「IPC」、どちらもなければ「停止」、デモ時は「デモ」。幅1180 px以下では省略する。詳細な「最終同期 N秒前 · systemd」はダッシュボード/写真の状態表示に残る。
- `App::start_ipc` がローカルIPCを購読し、接続・切断・イベントをGPUIタスクへ渡す。切断時は2秒後に再接続する。
  - スキャン進捗はデーモンカードへ即時反映し、完了時に一覧・統計・キューを再読込する。
  - 圧縮進捗・エラー変更・一時停止状態もイベントで即時反映する。
  - 接続できない間は上記の3秒更新がフォールバックとして動く。IPCエラーはモーダルにせず、デーモンカードに表示する。
  - デモモード（`--demo`）ではIPCを開始しない。

### 5.1 アプリのアップデート

- 設定画面の「起動と圧縮」の下に「アップデート」カードを置く。ナビゲーションの
  「設定」には更新がある間「更新」バッジを出す。
- カードは現在のバージョン、インストール形式（AppImage / Windows / deb /
  pacman / 開発ビルド）、最終確認時刻、自動確認スイッチ、「今すぐ確認」を表示する。
- 状態: 待機 / 確認中 / 最新 / 更新あり / ダウンロード中 / 準備完了 / 適用中 /
  エラー。ダウンロード中は進捗バーと受信量を出す。
- 「更新あり」ではバージョン、リリースノートへのリンク、ダウンロードを出す。
  ダウンロードと署名検証が終わると「更新して再起動」を出し、1回目で arm、
  2回目で適用する。
- deb / pacman はパッケージマネージャのコマンドとリリースページを出す。
  開発ビルド、ポータブル、Windows per-machine は自動適用できない旨を出す。
- 適用前にデーモンへ `shutdown` を送る。IPC未接続でデーモンが動いている場合は
  適用ボタンを無効にし、停止を促す。
- 自動確認の失敗はカードに出さない。手動確認の失敗、署名検証失敗、書き込み
  不可、適用失敗、ロールバックはカードとメッセージ行/リボンに出す。
- 前回の更新結果（成功・ロールバック）は `last-result.json` から一度だけ読み、
  カードに表示する。

## 7. デモと開発用フラグ

| フラグ | 動作 |
|---|---|
| `--demo` | 生成したサンプル画像と専用サムネイル・プレビュー、テンポラリDBで起動する |
| `--demo-reset` | 起動前にデモ用ディレクトリとDBを削除して作り直す |
| `--window-size WxH` | 初期ウィンドウサイズを指定（例: `1440x900`）。既定は1280×820 |
| `--background` | UIを開かず、デーモンのバックグラウンドスーパーバイザとして起動する |

- デモは18枚の1280×800 PNG（縦グラデーション、太陽、シルエット）と256 pxのPNGサムネイルを生成する。1200 pxプレビューは選択時にデモ専用の `previews/` へ生成する。
- 保存先はOSのテンポラリ領域 `vrc-photo-manager-demo/` 配下。DBは `library.db` で、再起動しても設定が残る。写真が空のときだけシードする。
- 実ライブラリのサムネイル／プレビューキャッシュには書き込まない。写真IDも実データと衝突しない。
- デモ中はサイドバー下部に `DEMO DATA` を表示する。

## 8. 実装上の注意と制約

- GPUIの `RenderImage` はBGRA前提。1200 pxプレビューは core の `preview` モジュール、256 pxサムネイルは UI の `decode_thumbnail` が背景でデコードし、UIスレッドでは `make_render_image` / `preview_render_image` でBGRA変換と `RenderImage` 化だけを行う。
- `gpui-pre` 0.3.9 には要素単位のバックドロップブラーがない。ガラスは`WindowBackgroundAppearance::Blurred` とアンビエント層で背景に限定し、カードは不透明パネルで分離する。カード内に半透明のブラーは使わない。
- `uniform_list` は行高固定のため、日付グループ化はしない。行高は列幅から3:2画像＋表示中のテキスト行として算出し、列数・行高が変わったときは表示中の先頭写真をアンカーに再配置する。
- 一覧・検索は全件を仮想表示する。索引は全件分（100kで約2.4 MB）、ページキャッシュは最大24ページ（6,144枚）、表示サムネイルは192件LRU。
- 100kのrelease測定は索引61.5 ms / ページ0.72 ms / warm初回フレーム179–187 ms、cold-ish 226–235 ms（空DB 158–163 ms）。cold-ishはXDG/Mesaキャッシュ等を新しくした測定で、OSページキャッシュは破棄していない。真のOS cold起動は未測定。
- 年レールはX11バックエンドの実XTest入力で1280×820 / 1440×900の年クリック・レール外ドラッグ・ホイールを確認済み。レール下のカードはホバー・クリックを受けない。WaylandセッションはXTestイベントを落とすため、Waylandでの実ポインタ確認は未実施。
- ライブラリグリッドの矢印キー移動は未実装。ビューアの `Left` / `Right` は上部バーにフォーカスがあるときだけ有効。
- `gpui-kit` のバージョンを上げる場合は、`uniform_list` / `img` / `Input` / `Switch` / `Theme` のAPIを実機確認する。
- UIからデーモンを起動する処理は `spawn_daemon_process`。`--background` は `run_background_supervisor`。
- `App` はDBを直接保持する。重い書き込みはデーモンに任せる。
- 3秒更新で一覧全体を再読込しないこと（サムネイル再デコードが重い）。枚数比較でガードしている。
- 見た目の基準はLinuxの1280×820 / 1440×900。Windows実機での確認は [#9](https://github.com/TommyZ-7/vrc-photo-manager/issues/9) で追跡する。

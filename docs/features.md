# 機能仕様（現行実装）

## 1. 写真の索引

- 対象: `.png` / `.jpg` / `.jpeg`（大文字拡張子も可）。
- VRChatのファイル名 `VRChat_YYYY-MM-DD_HH-MM-SS.mmm_WxH.png` から撮影時刻と解像度を解析する。
- 解析できない場合はファイル更新時刻を使う。
- 画像寸法を取得できないファイルは索引しない。
- `compressed/` サブディレクトリは走査対象外。
- 起動時に全走査し、以後は `notify` のイベントで変更ファイルだけを増分索引する。
- 索引時にBLAKE3を計算し、移動・改名・重複判定に使う。既存行の未計算ハッシュはデーモンがバックグラウンドで埋める。同じハッシュの写真には「重複」バッジを表示する。
- 手動移動は、設定済みルート内（写真フォルダ⇔取り込み先を含む）で同じ写真IDに再結合する。照合はBLAKE3を優先し、未計算時はファイル名・サイズ・寸法・撮影時刻を使う。コピーは別写真として残す。
- 外部で削除されたファイルは `status='missing'` になり、一覧から消える（DBからは消えない）。完了済みの圧縮版がある場合は `status='replaced'` として表示を継続する。
- 一覧・検索は、一致する写真の軽量索引（ID、撮影時刻UTC、ローカル撮影月）を1回読み、表示範囲の写真だけを256枚ページで取得する。全件を `Photo` 行としてメモリに載せない。

## 2. 文脈の記録

写真1枚に対して以下を保存する。

- 撮影日時（ローカル、UTC、オフセット）
- ワールドID・表示名・インスタンスID
- 撮影時の同接プレイヤー（ユーザーID、表示名）
- 撮影者（XMPがある場合）
- 取得元（`log` / `log+xmp` / `xmp` / `demo`）と信頼度

取得元と信頼度:

| 状況 | link_method | confidence |
|---|---|---|
| ログのセッションに一致 | `log` | 0.9 |
| ログ + XMP | `log+xmp` | 1.0 |
| ログなし、XMPのみ | `xmp` | 0.4 |
| デモデータ | `demo` | 1.0 |

- ログもXMPもない写真は未紐付けのまま。
- 未紐付け写真はログ取り込み後に再紐付けされる。
- プライベートワールドはXMPに名前が入らないことがある。その場合はワールドID表示または「未紐付け」になる。

## 3. 圧縮

### 3.1 対応形式

| 形式 | 透過 | ロスレス | 速度指定 | 備考 |
|---|---|---|---|---|
| JPEG | 非対応 | 非対応 | なし | 透過は背景合成 |
| WebP | 対応 | 対応 | なし | |
| AVIF | 対応 | 近似 | 1〜10 | `ravif` の制約でロスレスは品質100の近似 |
| JPEG XL | 非対応（現状αを落とす） | 対応 | 1〜10 | `jpegxl-rs` のα不具合回避 |

### 3.2 プロファイル

`CompressionProfile` の設定:

- 名前、有効/無効、自動適用
- 形式
- 品質 1〜100
- ロスレス
- リサイズ（有効/無効、幅、高さ、アスペクト比維持、リサイズ方法: 大きい場合のみ / 毎回）
- 出力先（未指定なら元写真の `compressed/`）
- サフィックス（出力ファイル名に付与、編集可能）
- エンコード速度 1〜10（AVIF / JXL）

現行UIで編集できるのは形式・品質・ロスレス・リサイズ（方法を含む）・サフィックス・出力先・自動適用。エンコード速度は保存値の表示のみ。

初回起動時に以下の既定プロファイルを作成する。

- WebP 高品質（Q82、自動ON）
- AVIF 容量優先（Q68、S6、自動ON）
- JPEG XL ロスレス（手動）
- JPEG 互換用（Q88、手動）

プロファイル一覧は `sort_order` の昇順で表示し、並び順は再起動後も維持する。自動圧縮はこの順に適用する。

- 一覧カードには名前、形式、品質/ロスレス、自動適用状態を表示する。
- 編集画面は「形式と画質」「リサイズ」「出力」に分け、自動適用スイッチには「自動圧縮に使う」と説明を付ける。変更は即時保存する。
- ロスレスはプロファイルごとに切り替えられる。WebP / JPEG XL はON/OFF、AVIFは「近似ロスレス（品質100）」、JPEGは非対応として無効化する。ロスレスON中は品質の増減を無効にする。
- リサイズ方法は「大きい場合のみ」（指定解像度を超える画像だけ縮小）と「毎回」（小さい画像も指定解像度に合わせて拡大）から選ぶ。既定は「大きい場合のみ」。
- サフィックスは入力欄で編集でき、空欄も可。ファイル名に使えない文字は `_` に置換する。
- 形式をJPEGへ変更したときは、`lossless` を自動的にOFFへ戻す。
- 一覧カードの ↑↓ で並び替える。先頭の ↑ と末尾の ↓ は無効。
- 「複製」は「〈名前〉のコピー」を元の直後に追加する。名前が衝突する場合は「のコピー 2」…と連番を付ける。複製は自動適用OFFで作る。
- 「削除」は確認ダイアログを出す。`waiting` / `pending` / `processing` のジョブが参照している間は削除できず、完了後に削除できる。最後の1件も削除できない。完了済みジョブとderivativeは履歴として残る。

### 3.3 自動圧縮

- デーモン起動後に新規索引された写真が対象。
- 有効かつ自動ONのプロファイルを一覧の並び順に適用する。
- 元画像の扱いは自動圧縮専用の `auto_compress_keep_original`（既定 `true`）に従う。旧 `compression_keep_original` は読み込み時に引き継ぐ。
  - `true`: 別ファイルを生成し、元画像を保持する。
  - `false`: 圧縮成功後に元画像をOSゴミ箱へ移動する。自動圧縮がONのときは設定画面に警告を表示する。
- 圧縮ファイルの存在・非空の検証に失敗した場合、元画像は変更しない。
- `auto_compress_immediate`（既定 `true`）で実行契機を選ぶ。
  - `true`: 新規写真を `pending` で積み、デーモンが即時処理する。
  - `false`: 新規写真を `waiting` で積み、ダッシュボードの「待機をすべて圧縮」を押すまで処理しない。
- 初回スキャン分のバックログは `auto_compress_backlog` で制御する。false（既定）なら初回スキャンで見つかった既存写真は圧縮せず、true なら圧縮する。

### 3.4 手動圧縮

- ライブラリ／検索で写真を選択して手動圧縮ダイアログを開く。複数選択時は、選択した全件を一度にキューへ積む。
- ダイアログで登録済みプロファイルを1つ選ぶ。
- 出力先は次の3つから選ぶ。
  - **指定したフォルダ**: 実行のたびにフォルダを選ぶ。出力先は `compression_jobs.output_dir` に保存し、プロファイルの出力先より優先する。
  - **プロファイル指定のフォルダ**: プロファイルの `output_dir` を使う。未設定なら元画像の隣の `compressed/`。
  - **クリップボード**: 1枚選択時のみ。プロファイルのリサイズ設定を適用したPNGをコピーする。元画像とライブラリは変更せず、ジョブも積まない。
- 指定フォルダ／プロファイル指定フォルダでは、元画像を保持するかOSゴミ箱へ移動するかを毎回選ぶ。自動圧縮の設定は使わない。
  - `keep`: 圧縮版を別ファイルで生成。元画像は残す。
  - `replace`: 圧縮ファイルのサイズ検証後、`photos.display_derivative_id` を設定して `status='replaced'` にし、元画像をOSゴミ箱へ移動する。ライブラリには同じ写真カードとして残り、タグ・メモ・文脈を維持する。
- 出力名が既存ファイルと衝突する場合は連番を付ける。既存ファイルは上書きしない。
- 圧縮に失敗した場合、元画像は変更しない。

### 3.5 キュー

- `compression_jobs` に永続化し、全プロファイルで共有する。
- 状態は `waiting` / `pending` / `processing` / `completed` / `failed` / `cancelled`。
  - `waiting`: 自動圧縮の即時実行がOFFのときに積まれる未実行状態。ワーカーは取得しない。
  - `pending`: 実行待ち。ワーカーが取得する。
- ワーカー数は設定で1〜4（既定1）。
- 二重取得を防ぐため、SQLiteの単一UPDATEで `pending` を `processing` にする。
- ダッシュボードに共有キューを表示し、全プロファイルのジョブをプロファイル名付きで確認できる。未完了・未実行・失敗の件数を表示する。
- `waiting` があるときは「待機をすべて圧縮」で一括して `pending` に戻し、デーモンを起こす。設定をONに戻しただけでは既存の待機ジョブを自動解放しない。
- 一括解放時は、その時点の `auto_compress_keep_original` を各ジョブの `policy` に再適用する。待機中に設定を変更しても、解放時の設定が使われる。
- 一括解放が `replace` になる場合は、実行前に確認ダイアログを出す。キューの上部には現在の「自動: 元画像を保持 / 置換」をバッジ表示する。
- 手動圧縮ジョブは `output_dir` を持つことがある。`NULL` はプロファイルの出力先を使う。
- デーモンは2秒ごと、および差分索引の直前に圧縮関連の設定を再読込する。実行中のデーモンでも、元画像ポリシーと即時/待機の変更が次の自動圧縮から反映される。
- 失敗したジョブは `failed` として残り、圧縮キューに写真名・プロファイル名・失敗理由（`error`）を表示する。
- 失敗ジョブは個別または一括で再試行できる。ユーザー操作による再試行はジョブごとに最大3回（`retry_count`）。
  - 再試行は写真・プロファイル・方針（`keep` / `replace`）を変えず、進捗・エラー・開始/終了時刻をリセットして `pending` に戻す。
  - 「失敗をすべて再試行」は上限に達したジョブを除外し、戻した件数を表示する。
  - 上限到達後は写真インスペクタから新しいジョブを積む（新しいジョブは再試行回数0から始まる）。
- 自動再試行はしない。

## 4. 取り込み

- UIの「コピー取込」「移動取込」からファイルを選択する。
- 取り込み先は設定の `managed_dir`。未設定ならユーザーデータディレクトリの `imported/`。
- 名前衝突は `-1`, `-2` の連番。
- コピーは一時ファイル→サイズ検証→リネーム。
- 移動は同一ファイルシステムなら `rename`、失敗時はコピー後に元ファイルを削除。
- 取り込み先を `library_roots` に `managed` として登録し、索引・紐付け・サムネイル生成を行う。
- 元ファイルを残すか移動するかは操作ごとに選ぶ。
- ファイル単位で処理を継続し、1ファイルの失敗でバッチ全体を中断しない。
  - 失敗したファイルは元パスと理由を「取り込み結果」パネルに残す。コピー失敗など再試行可能なものはパネルから再試行できる。存在しないファイルなど再試行不能なものも元パスと理由を表示する（「再試行」ボタンは出ない）。
  - 移動取り込みで、移動先へのコピーは成功したが元ファイルを削除できなかった場合は「部分移動」として扱う。移動先のファイルは取り込み済みに数え、警告として表示する。元ファイルは残るため再試行しない。
  - 取り込み先フォルダを作成できない場合は、バッチ全体のエラーになる。

## 5. 検索

- ワールド（表示名・ワールドID・インスタンスIDの部分一致）
- プレイヤー（表示名・ユーザーIDの部分一致）
- タグ（部分一致）
- 日時（今日 / 7日 / 30日 / すべて）
- お気に入り
- カテゴリ間はAND、カテゴリ内はOR。
- 結果は件数上限なしで、全件を仮想グリッドに表示する。件数は索引の総数で、読み込み済みカード数ではない。
- 検索はバックグラウンドで実行し、検索中も前回の結果を表示する。
- 検索結果にもライブラリと同じ年レールを表示する。
- タグを編集したとき、有効な検索にタグ条件があれば同じ条件を再実行し、結果を更新する。スクロール位置は先頭写真を基準に維持する。

### 5.1 年レール

- 一覧・検索の右端に年レールを表示する。写真が0枚のときは表示しない。
- 年ラベルは新しい年から順に、その年より新しい写真の累計枚数に比例した位置へ置く。
- 年ラベルをクリックするとその年の先頭写真へ移動する。レール上をドラッグすると任意の位置へ移動する。
- 現在表示中の先頭写真の月を `YYYY年M月` のピルで表示し、スクロールに追従させる。
- レールの描画は索引とスクロール位置だけを参照し、DBクエリや画像デコードを行わない。
- レールは下のカードへのホバー・クリックを遮断し、ホイールスクロールだけを通す。

## 6. 写真詳細

- プレビュー（長辺1200pxに縮小してデコード）
- ワールド、インスタンス、撮影者、取得元
- 撮影時の同接プレイヤー
- タグ追加・削除
- メモ表示・編集（空・空白のみは未設定として保存）
- 圧縮履歴
- お気に入り
- 圧縮、ゴミ箱移動

## 7. 削除

- OSのゴミ箱へ移動するのみ。完全削除は提供しない。
- 2段階確認（1回目でメッセージ、2回目で実行）。
- 完了済みの圧縮版がある場合は、元画像削除後も `replaced` として同じカードを表示し続ける。
- 圧縮版もない場合は `missing` にして一覧から隠す。DBの行とメタデータは残す。

## 8. トレイ・自動起動

- デーモンがトレイアイコンを持つ。
  - Windows: `tray-icon` + Win32メッセージポンプ
  - Linux: `tray-icon` の `ksni` バックエンド（StatusNotifierItem / D-Bus）
- メニュー: UIを開く、監視の一時停止/再開、状態表示、終了。
- UIが起動していない間も監視と自動圧縮を継続する。
- OSログイン時の自動起動を設定できる。
  - 通常: デーモン実体を登録。
  - AppImage: `$APPIMAGE --background` を登録。UIの `--background` がデーモンを子プロセスで起動して待機する。
  - deb/pacman: 任意の systemd ユーザーサービス `vrc-photo-daemon.service` を同梱する。利用者が明示的に enable した場合のみサービスとして起動し、アプリ管理の自動起動もフォールバックとして残る。
- デーモンは `single-instance` で二重起動を防ぐ。
- Linuxでトレイが使えない環境ではヘッドレスで継続する。

### 8.1 UI⇔デーモンIPC

- トランスポートはローカルソケット（Unix domain socket / Windows名前付きパイプ）。TCPやネットワーク公開は使わない。
- プロトコルは改行区切りJSON、`PROTOCOL_VERSION = 1`。接続は `hello` で始まり、バージョン不一致なら接続を閉じる。
- リクエスト: `status`、`wake_commands`、`wake_jobs`、`set_paused`、`shutdown`、`subscribe`。
- UI操作:
  - ダッシュボードの「再スキャン」は `daemon_commands` に積み、IPC接続中なら `wake_commands` で即時実行する。
  - 「監視を一時停止/再開」は `set_paused` を送る。停止中はボタンを無効化する。
  - 「デーモンを終了」は2回押しで `shutdown` を送る。
  - 圧縮キュー投入後は `wake_jobs` を送り、ワーカーを即時起床する。
- イベント:
  - `scan_started` / `scan_progress`（walking / indexing、root番号、処理数） / `scan_finished`
  - `compression_progress`（job_id、photo_id、status、progress、error）
  - `daemon_error_changed`（scan / log / link）
  - `status_changed`（paused、scanning、photo_count、pending_jobsなど）
- UIはイベントで即時更新し、接続できない間はハートビートと3秒ポーリングにフォールバックする。圧縮進捗は開始・完了・失敗の段階値で、エンコーダの真の%ではない。
- デーモンはIPCハンドラでSQLiteを触らない。長時間スキャン中でも `status` / `wake` / `pause` / `shutdown` に応答できる。

## 10. エラー表示と再試行

失敗の詳細は原因の画面に置き、全画面共通の通知バーから移動できる。

- グローバル通知バー: 圧縮失敗・デーモンの処理エラー・取り込み失敗がある間、全画面の上部に赤い通知バーを出す。バーは件数だけを示し、「ダッシュボードを開く」「写真を開く」で詳細画面へ移動する。閉じる操作はなく、状態が解消するか取り込み結果を閉じると消える。
- 圧縮: ダッシュボードの共有キューに失敗ジョブ（最新100件）を表示する。各行に写真名、プロファイル名、失敗理由、`再試行 n/3` を出し、上限未満なら「再試行」を出す。「失敗をすべて再試行」は、読み込んだ最新100件に再試行可能な失敗が1件でもあると出し、実行時はDB上の再試行可能な全件（100件より古いものも含む）を対象にする。上限到達時は「再試行の上限（3回）に達しました」と表示する。
- 取り込み: 写真画面の「取り込み結果」パネルに、取り込み数・スキップ数・失敗数・部分移動数を出す。失敗ファイルは元パスと理由を、部分移動は移動元・移動先・削除失敗の理由を、索引できなかったファイルはパスと理由を表示する。「失敗分を再試行」は再試行可能な失敗だけを同じ取り込み先・モードで再実行する。取り込みの再試行回数に上限はない。
- デーモン: ダッシュボードの「処理エラー」カードに、操作（写真スキャン / ログ解析 / 写真の紐付け）ごとのメッセージ、詳細、検出回数、発生時刻を表示する。「再試行」は `daemon_commands` にコマンドを積み、IPC接続中なら `wake_commands` で即時実行する。デーモン停止中はキューに残り、起動後に実行される。処理が成功すると行は消える（ログ解析は、新しく処理できた行が1行以上あり、失敗もスキップもない場合）。
- ログ: UIとデーモンは `<data_dir>/logs/` にログを書く。ファイル名は `vrc-photo-manager.log`（UI）と `vrc-photo-daemon.log`（デーモン）。起動時に10 MiB以上なら `vrc-photo-manager.log.1` のような `.1` ファイルへローテーションする。ダッシュボードと設定画面の「ログ」カードに保存先とファイル名を表示し、「ログフォルダを開く」でOSのファイラーを開く。

## 10. アプリのアップデート

- フィードは GitHub Releases の署名付き `latest.json`。マニフェストは
  `linux-x86_64`（AppImage）と `windows-x86_64`（NSIS）の成果物URL、サイズ、
  SHA-256、minisign署名を持つ。
- UI起動15秒後に自動確認し、以後1時間ごとに期限（24時間）を確認する。
  設定「アップデートを自動確認」でOFFにできる。手動の「今すぐ確認」は常に使える。
- 自動確認の失敗はログだけに残し、UIには出さない。手動確認の失敗は設定画面に出す。
- 更新があると設定のナビゲーションに「更新」バッジを出し、設定画面の
  「アップデート」カードにバージョン、リリースノート、ダウンロード、
  再起動して適用を表示する。適用は2回押しで確定する。
- ダウンロードはマニフェストのサイズ上限（300 MiB）とSHA-256、minisign署名を
  検証する。検証に失敗したファイルは削除し、現行版を維持する。
- AppImage と current-user の Windows NSIS は `vrc-photo-updater` ヘルパーが
  旧版を退避して置換し、新UIの健康マーカーを確認する。45秒以内に確認できない
  場合は旧版へ戻して再起動する。旧版は `<AppImage>.previous` または
  `<data_dir>/updates/backup/<version>/` に残る。
- deb / pacman は自己置換しない。更新があるとパッケージマネージャのコマンドと
  リリースページを表示する。開発ビルド、ポータブル、Windowsのper-machine
  インストールも自動適用の対象外。
- 更新の結果（成功・ロールバック・失敗）は `last-result.json` に残り、次回起動時に
  一度だけ表示する。詳細は `<data_dir>/updates/updater.log`。
- 自動確認はUI起動中のみ。デーモンだけが動いている間は確認しない。

## 11. 現行の制約

- 一覧・検索の件数上限はない。100k合成DB（`photo_context` 5万行を含む）でrelease性能（索引61.5 ms、ページ0.72 ms、warm初回フレーム179–187 ms、cold-ish 226–235 ms、空DB cold-ish 158–163 ms）を測定済み。真のOS cold起動（ページキャッシュ破棄後）は未測定。
- ページキャッシュは最大24ページ（6,144枚）、サムネイルは192件LRU。年レールはX11の実XTest入力で1280×820 / 1440×900の年クリック・レール外ドラッグ・ホイールを確認済み。WaylandはXTestイベントを落とすため未確認。
- 言語は日本語のみ。
- UIのキーボードショートカット、圧縮確認モーダルは未実装。
- ローカルIPC（Unix domain socket / Windows名前付きパイプ、改行区切りJSON）で即時wake-upとイベント配信を行う。UIとデーモンは引き続きSQLiteを共有し、処理エラー（`daemon_errors`）と再実行要求（`daemon_commands`）の正はDBに置く。IPCはコマンドを挿入せず、`wake_commands` / `wake_jobs` でデーモンを起こすだけ。
- IPCイベント: スキャン開始・進捗・完了、圧縮の開始・完了・失敗、デーモンエラー変更、一時停止状態の変更。UIはイベントで即時更新し、接続できない間は3秒ポーリングにフォールバックする。
- 稼働判定はハートビートが20秒以内、またはIPC購読が接続中であること。長時間スキャン中にハートビートが古くなっても「デーモン停止」と誤表示しない。
- Windows実機のトレイ・IME・自動起動は未検証。
- AppImageの実起動、deb/pacmanのインストール確認は未実施。
- ディスク上のサムネイルキャッシュのLRU削除は未実装（メモリ上の表示サムネイルは192件LRU）。

# テスト方針

## 1. 自動テスト

### 実行

```bash
cargo test --workspace
```

2026-10-24時点:

- `vrc-photo-core`: 62件
- `vrc-photo-daemon`: 21件
- UI: 59件（GPUIを起動しない純粋ヘルパーの単体テスト）

### coreの主なテスト

| ファイル | 内容 |
|---|---|
| `db.rs` | マイグレーション（V4の再実行を含む）、写真UPSERT、文脈/プレイヤー、検索、キューの原子的取得、`retry_count` と再試行上限、`daemon_errors` のUPSERT/削除、`daemon_commands` の重複排除と取り出し |
| `scanner.rs` | フォルダ走査、単一ファイル索引、compressed除外、読めないファイル・ディレクトリの失敗記録 |
| `photo_filename.rs` | VRChatファイル名、無効名、拡張子 |
| `log_parser.rs` | イベント解析、セッション、入退室 |
| `linker.rs` | ログ紐付け、XMPのみの紐付け |
| `metadata.rs` | XMP属性、PNG iTXtからの読み取り |
| `compressor.rs` | WebP/JPEG、リサイズ、出力名衝突回避 |
| `thumbnail.rs` | サムネイル生成、キャッシュ、存在しない元ファイル |
| `importer.rs` | コピー、移動、衝突連番、非画像スキップ、ファイル単位の失敗継続、部分移動（コピー成功・元削除失敗） |
| `settings.rs` | 設定JSONの往復、パス検出 |
| `logging.rs` | ログファイルの作成・追記・サイズ超過時のローテーション |

### daemonの主なテスト

- ログの不完全行を次回に回す。
- 最新ログファイルの選択。
- 写真 + ログのE2E（索引 → 紐付け → 外部削除でmissing）。
- 自動圧縮E2E（プロファイル → キュー → 圧縮 → derivative）。
- notify相当の増分索引。
- 写真フォルダが見つからないときに `scan` エラーを記録し、フォルダ作成後の `rescan` で消える。
- 失敗のあるルートスキャンでは、そのルートの写真をmissingにしない。
- 不正なログフォルダで `log` エラーを記録し、正しいフォルダと `relog` で消える。
- 失敗ジョブをDBで作り、再試行 → 圧縮 → 完了まで通す。
- `daemon_commands` の処理で設定を再読込し、新しいルートの監視を張り直す。
- `run_once` が処理前にコマンドを消化する。

### UIの主なテスト

GPUIのウィンドウは開かず、表示に使う純粋関数だけを検証する。

- 通知バーの優先順位（圧縮 → デーモン → 取り込み）。
- デーモン操作のラベルと再試行コマンドの対応。
- 取り込み結果の失敗数・部分移動数の集計と、再試行対象（`Failed` かつ `retryable`）の抽出。
- 圧縮ジョブの再試行可否と `再試行 n/3` の表示（0回・2回・上限3回）。
- タイムスタンプの `MM/DD HH:MM` 変換と生文字列フォールバック。

## 2. 追加すべきテスト

## 3. 手動確認チェックリスト

リリース前・大きなUI変更後に実施する。

### 写真索引

- [ ] VRChat写真フォルダを指定して起動すると一覧に出る
- [ ] 新規PNGを追加すると自動で出る
- [ ] `compressed/` 内の生成物が写真として索引されない
- [ ] 外部で削除した写真が一覧から消える
- [ ] 同名・別パスの写真が別エントリになる

### ログ・XMP

- [ ] ワールド参加後に撮った写真へワールド名が付く
- [ ] 入室中のプレイヤーが写真に付く
- [ ] 退出済みプレイヤーが付かない
- [ ] ログがない写真にXMPの撮影者/ワールドが付く
- [ ] プライベートワールドでID表示になる
- [ ] 24時間より前のログがない場合、未紐付けのままになる

### 圧縮

- [ ] 自動圧縮で元画像が残る
- [ ] 手動 `keep` で別ファイルができる
- [ ] 手動 `replace` で元画像がゴミ箱へ移る
- [ ] 出力名衝突で連番になる
- [ ] 出力先に書き込めない場合、ジョブがfailedになり元画像が残る
- [ ] キューがデーモン再起動後も再開する
- [ ] プロファイルの ↑↓ 並び替えが再起動後も残る
- [ ] 複製が元の直後に入り、名前が重複しない
- [ ] 複製を編集しても元のプロファイルが変わらない
- [ ] 削除確認でキャンセルすると何も消えない
- [ ] 未完了ジョブがあるプロファイルは削除できない
- [ ] 最後の1件のプロファイルは削除できない
- [ ] 自動圧縮がプロファイルの並び順どおりにキューへ入る
- [ ] 失敗ジョブに写真名・プロファイル名・失敗理由・`再試行 n/3` が出る
- [ ] 個別の「再試行」でジョブがキューに戻り、完了する

- [ ] 3回再試行したジョブ（`retry_count=3`）は再試行できず、上限メッセージが出る

### エラー表示・再試行

- [ ] デモDBに失敗ジョブと `daemon_errors` の行を入れ、全画面の通知バーに圧縮失敗・デーモンエラーが出る
- [ ] 通知バーの「圧縮を開く」「ログ監視を開く」で対象画面へ移動する
- [ ] 有効なファイルと存在しないパスを同時に取り込み、成功分が処理され、失敗ファイルの元パスと理由が「取り込み結果」パネルに出る
- [ ] 「失敗分を再試行」が再試行可能な失敗だけを再実行する
- [ ] 移動取り込みで元ファイル削除を失敗させ、部分移動が警告として出る（取り込み済みに数え、再試行対象にしない）
- [ ] ログ監視画面の「処理エラー」カードに操作・メッセージ・詳細・検出回数・時刻が出る
- [ ] 「再試行」で `daemon_commands` にコマンドが入り、デーモンが処理してエラーが消える

- [ ] 写真フォルダを一時的に消してスキャンエラーを出し、戻して「再試行」で解消する

## 4. 既知の未検証範囲

- deb/pacmanのインストール後起動
- 10万枚の実ライブラリ負荷（合成DBでwarm初回179–187 ms、cold-ish 226–235 ms、空DB cold-ish 158–163 ms、索引61.5 ms、ページ0.72 msを測定済み。cold-ishは予算内だが真のOS cold起動は未測定。実ライブラリでの確認は未検証）

- 実VRChatログの最新バージョン差異
- rfdのファイルダイアログ（xdg-portal環境）
- エラー表示・再試行・ログカードの実画面確認（デモDBに失敗ジョブと `daemon_errors` を入れて行う。UIの自動テストは純粋ヘルパーのみ）

## 5. CI

- PR: `test` ジョブ（fmt / clippy / test）。docs-onlyはfast-pass。
- PR（release-relevant paths）: Releaseワークフローで3形式をビルド。
- tag: 3形式をビルドしGitHub Releaseへ添付。
- `main` の必須チェックは `test`。

## 6. テスト追加のルール

- バグ修正には再現テストを追加する。
- ログ解析は匿名化した実ログフィクスチャを使う。
- 画像テストは小さな生成PNGを使い、外部ファイルに依存しない。
- サムネイルやインポートのテストは一時ディレクトリを使い、ユーザーデータディレクトリを汚さない。

# ADR-0019: AI 自動タグ付けは署名済み sidecar プラグインとして分離する

- Status: Accepted
- Date: 2026-11-04
- Related: [#198](https://github.com/TommyZ-7/vrc-photon/issues/198)

## Context

VRChat のスクリーンショットを、撮影後の手作業なしで「キャラクターの有無」
「人数」「場所」で整理したい。推論には d1-2B（LFM3-VL-2B ベース、約 1.9B）の
GGUF を使い、写真は外部へ送らず、すべてローカルで完結させる。

推論部分は次の性質を持つ。

- モデルと mmproj だけで約 2 GB あり、BOOTH の 1 ファイル 1.2 GB 制限に収まらない。
- GPU ドライバ、VRAM/RAM、llama.cpp のバックエンドに依存し、クラッシュ・OOM が
  起こり得る。
- 有償配布する予定で、GPL-3.0-or-later の本体とはライセンスとリリースサイクルが
  異なる。
- Windows / Linux、CUDA / ROCm / Vulkan / CPU の組み合わせを配布する必要がある。

本体は無料・公開のまま、推論側を別配布にする。方式の候補:

- 本体デーモンに llama.cpp を直接組み込む: 配布は単純になるが、推論の
  クラッシュや OOM が索引・圧縮・UI を巻き込む。有償コードと GPL コードが
  同じバイナリに混ざり、モデル更新も本体リリースに縛られる。
- クラウド推論: モデル配布は不要になるが、写真を外部送信しない方針に反する。
- UI プロセスが sidecar を起動する: UI を閉じると推論が止まり、状態変更の
  所有者が UI とデーモンに分裂する。
- OS パッケージとしてバックエンド別に配布する: 配布チャネルと更新が
  OS に縛られ、Windows 展開が難しい。

また、v1 の販売方針として、製品ライセンスの入力・サーバー照会・機械バインドを
実装しないことが決まっている。購入した ZIP を取り込めば全機能を使えるように
し、ZIP のコピーによる共有リスクは許容する。一方で、改ざん・破損・別配布物の
取り違えは防ぐ必要がある。

## Decision

1. **sidecar 分離**: 推論は別リポジトリ（非公開・プロプライエタリ）の
   常駐プロセス `d1-sidecar` が行う。本体は stdin/stdout の UTF-8 JSON Lines で
   意味的な操作（presence / people_count / place_class / place_tags）だけを
   要求する。sidecar は DB・UI・ネットワークアクセスを持たず、本体は
   sidecar のプロンプトや llama.cpp の型に依存しない。
2. **ホストが状態変更を所有**: プラグイン ZIP の取込、probe、モデルの
   ダウンロード・取込・削除、sidecar の起動・監視・停止、タグ付けジョブの
   実行と AI 結果の書き込みは、すべてデーモンが所有する。UI はファイル選択と
   設定の保存、ジョブの enqueue を行い、取込・モデル・probe・キャンセルは
   IPC v5 でデーモンに要求する。UI は `ai-host` に依存せず、`core` と `ipc`
   だけを使う。SQLite が耐久データの正で、UI は 3 秒ポーリングへ
   フォールバックできる。
3. **AI タグは別テーブル**: スキーマ v13 で `photo_ai`（有無・人数・場所）と
   `photo_ai_tags`（タグ別確率）を追加し、既存の `tags` / `photo_tags`
   （手動タグ）は一切変更しない。AI タグの表示・検索・削除は手動タグと
   SQL レベルで分離する。
4. **ZIP 署名は整合性のみ**: プラグイン ZIP の `manifest.json` を minisign で
   署名し、本体は埋め込み公開鍵で検証する。`manifest.files` の SHA-256 と
   サイズも展開時に検証し、成功したものだけを確定する。これは DRM ではなく、
   改ざん・破損・別配布物の取り違えを防ぐ整合性チェックである。
5. **v1 は製品ライセンスなし**: ライセンスファイル、キー入力、サーバー照会、
   機械バインドを持たない。ZIP を取り込めば全機能を利用できる。ZIP の
   コピーで購入者以外も使えるリスクは許容し、必要になった時点で v2 に
   ライセンス検証を追加する。その場合も sidecar 通信規約には影響させない。
6. **M2 は開発鍵**: M2 の debug ビルドだけが `packaging/ai/dev-keys.txt` の
   開発用公開鍵を読み、開発用署名 ZIP を受け入れる。release ビルドは M3 で
   本番鍵を埋めるまで空の鍵リストを持ち、すべての ZIP を拒否する。
   secret key はリポジトリにコミットしない。

## Consequences

- 推論のクラッシュ・OOM・GPU ドライバ異常が本体の索引・圧縮・UI を巻き込まない。
  デーモンは sidecar の終了をジョブ失敗として扱い、本体は落とさない。
- 有償コードと GPL の本体をプロセス境界と別リポジトリで分離できる。公開側は
  通信規約・ホスト実装・DB・UI だけを持つ。
- モデルと llama.cpp の更新を本体のリリースサイクルから独立して配布できる。
- プロセス監視、タイムアウト、キャンセル、再起動、ログ転記の実装コストが増える。
- モデルが約 2 GB あるため、初回ダウンロードまたはオフライン取込が必要になる。
  ダウンロードは署名済み manifest の HTTPS URL にだけ接続し、写真・パス・
  推論結果は送信しない。
- プラグインの公開鍵と manifest の互換性管理が必要になる。protocol のメジャー
  不一致、host バージョン範囲外、platform/variant 不一致は取込時に拒否し、
  hello でも再確認する。
- 同一 `plugin_id` の variant 違いは共存でき、active は 1 つに限る。旧 version は
  ロールバック用に残せる。モデルは `plugin_id` 単位で共有する。
- 製品ライセンスがないため、ZIP のコピーによる利用を技術的に防げない。
  売上損失のリスクは残る。ライセンス検証を追加する場合は、通信規約を変えずに
  v2 で行う。
- M2 で実機検証するのは Linux Vulkan / CPU だけ。Windows は M3、CUDA / ROCm は
  M6 まで「未検証」と表記する。タグ精度・presence の誤検出・人数一致の品質検証は
  今回のスコープ外で、販売前に別途手動で行う。
- 公開ドキュメント（本 ADR、公開ホスト設計、`docs/architecture.md`、
  `docs/data-model.md`、`docs/security-privacy.md`、`docs/development.md`）を
  実装と同期させる必要がある。

## Alternatives

- **本体デーモンに llama.cpp を組み込む**: 単一バイナリで IPC も不要だが、
  推論のクラッシュが本体を巻き込み、有償コードと GPL コードが同じバイナリに
  混ざる。モデル更新も本体リリースに縛られるため不採用。
- **クラウド推論**: モデル配布と GPU 要件をなくせるが、写真を外部送信しない
  方針に反するため不採用。
- **UI プロセスが sidecar を所有する**: UI を閉じると推論が止まり、デーモンだけが
  動く間のタグ付けを継続できない。状態変更の所有者も分裂するため不採用。
- **バックエンド別の OS パッケージ**: 配布は楽になるが、更新が OS に縛られ、
  Windows 展開と有償コードの分離が難しいため不採用。署名済み ZIP を採用する。
- **製品ライセンスサーバーを v1 に導入**: アカウント・サーバー・オフライン利用の
  制約が増える。v1 はライセンスなしとするユーザー決定に反するため不採用。
  必要なら v2 で追加する。
- **ZIP 署名なし**: 実装は減るが、改ざん・破損・別配布物の取り違えを検出できない。
  既存の minisign 検証を再利用できるため、署名ありを採用する。
- **universal 1 パッケージ**: モデルが 1.2 GB を超え、バックエンドごとの
  動的ライブラリも異なる。`<platform>-<backend>` の variant 分割を採用する。

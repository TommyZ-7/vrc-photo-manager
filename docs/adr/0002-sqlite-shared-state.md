# ADR-0002: UIとデーモンはSQLiteを共有する

- Status: Accepted
- Date: 2026-10-21

## Context

UIと常駐デーモンを別プロセスにし、写真索引・ログ解析・圧縮キューを共有する必要がある。初期実装でIPCを入れると、プロトコル、再接続、バージョン整合、認証の設計が必要になる。

## Decision

- SQLite（WAL）を唯一の共有状態とする。
- UIはDBを直接読み、タグ・お気に入り・メモ・手動圧縮ジョブなどの短い書き込みを行う。
- デーモンは写真・ログ・圧縮・サムネイルの重い書き込みを行う。
- 圧縮ジョブの取得は単一の `UPDATE ... RETURNING` で原子的に行う。
- デーモンの稼働状態は `app_settings.daemon_heartbeat` で共有する。

## Consequences

- IPCなしでUIとデーモンを分離できる。
- DBスキーマが実質的なAPIになる。変更時は両プロセスの互換性に注意する。
- UIとデーモンの同時書き込みはWALと `busy_timeout` で吸収する。頻繁な競合が出たらIPCを再検討する。
- UIからデーモンへの即時コマンド（再スキャン等）は未実装。必要ならIPCを追加する。

## Alternatives

- 名前付きパイプ / UnixソケットのJSON-RPC: 即時コマンドとイベントに向くが、実装量が増える。
- ローカルHTTP: デバッグは楽だが、ポート管理と認証が必要。

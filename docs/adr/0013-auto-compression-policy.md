# ADR-0013: 圧縮ポリシーを全体設定にし、自動圧縮にも適用する

- Status: Accepted
- Date: 2026-10-25
- Supersedes: [ADR-0004](0004-compression-policy.md)

> ADR-0004 の「自動圧縮は元画像を保持固定、手動時のみ都度選択」を置き換える。履歴として残す。

## Context

ADR-0004 では、自動処理で写真を不可逆に変更しないことを優先し、自動圧縮は元画像を保持固定、手動圧縮だけが `keep` / `replace` を選べる設計だった。

その後、圧縮設定を整理するにあたり、次の運用が求められた。

- 元画像を保持するかどうかを、手動・一括・自動圧縮で同じ設定として扱う。
- 自動圧縮でも容量を削減したいユーザーが、明示的に置換を選べるようにする。
- 新規写真をすぐ圧縮するか、待機キューに積んで後からまとめて圧縮するかを選べるようにする。
- 自動圧縮が元画像をゴミ箱へ移す設定のときは、設定画面で警告する。

## Decision

- `AppSettings.compression_keep_original`（既定 `true`）を、手動圧縮・待機キューの一括圧縮・自動圧縮の共通ポリシーにする。
- `compression_keep_original=false` のとき、自動圧縮ジョブも `policy='replace'` で積む。
- `replace` は圧縮ファイルの存在・非空を検証した後にだけ元画像をOSゴミ箱へ移動する。圧縮や出力検証に失敗した場合は元画像を変更しない。
- 自動圧縮がONかつ `compression_keep_original=false` のとき、設定画面に「自動圧縮でも元画像をOSゴミ箱へ移動する」旨の警告を表示する。
- `AppSettings.auto_compress_immediate`（既定 `true`）を追加する。
  - `true`: 新規写真を `pending` で積み、デーモンが即時処理する。
  - `false`: 新規写真を `waiting` で積み、ワーカーは処理しない。ダッシュボードの「待機をすべて圧縮」で `waiting` を `pending` に一括変更したときだけ処理する。
- 圧縮キューは全プロファイル共有とし、ダッシュボードに表示する。

## Consequences

- 自動圧縮でも容量を削減できる。
- 既定は元画像保持のため、アップグレード直後に自動で写真がゴミ箱へ移ることはない。
- 置換を選んだ場合は、自動処理でも元画像がOSゴミ箱へ移る。警告と既定値で誤操作を抑えるが、ユーザーはゴミ箱を空にしない限り復元できる。
- 待機キューを使う場合、ユーザーが明示的に一括実行するまで圧縮されない。
- 失敗時に元画像が残る安全側の挙動は維持される。

## Alternatives

- 自動圧縮を `keep` 固定のままにする: ユーザーの要望と一致しないため不採用。
- プロファイルごとに元画像ポリシーを持たせる: 設定が増え、同じ写真に複数プロファイルを適用したときの扱いが複雑になるため不採用。
- 自動圧縮のたびに確認する: 撮影のたびに操作が必要になり、自動化の意味がなくなるため不採用。
- 元画像を完全削除する: 復元できないため不採用。置換はOSゴミ箱のみとする。

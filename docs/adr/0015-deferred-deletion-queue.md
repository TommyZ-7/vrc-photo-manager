# ADR-0015: 削除は依存ジョブのドレイン後に実行する

- Status: Accepted
- Date: 2026-10-29
- Related: [#143](https://github.com/TommyZ-7/vrc-photo-manager/issues/143), [#142](https://github.com/TommyZ-7/vrc-photo-manager/issues/142)

## Context

削除（置換に伴う元画像の自動削除、手動削除）と非同期ジョブ（圧縮キュー、将来の送信 outbox）の実行順序が保証されていなかった。

自動プロファイルが複数あり、`replace` で元画像を残さない場合、ワーカー数によって結果が変わっていた。

- ワーカー1: 1件目の replace が元画像をゴミ箱へ移す。2件目は表示中の派生を入力に再圧縮し、1件目の派生ファイルをゴミ箱へ移す。静かに二重圧縮が起きる。
- ワーカー2以上: 両方が元画像を読み、両方が同じ元画像をゴミ箱へ移そうとして後着が失敗する。ジョブの成否がタイミング依存になる。

また、手動削除がUI内で即時実行されるため、圧縮中・送信待ちの写真を消すと後続ジョブが壊れる。デーモン再起動時に削除が途中で放置される問題も避ける必要がある。

## Decision

- 削除をSQLiteの `deletion_requests` に積み、デーモンの削除エグゼキュータが実行する。UIは要求を書いて `wake_jobs` を送るだけで、ファイルを移動しない。
- 写真に `deleting` 状態を追加する。手動削除の要求時に即座に一覧から外し、この状態の写真には新しい圧縮ジョブを積まない。
- 削除のブロック対象は、その写真を対象とする全ジョブ（圧縮、将来の送信 outbox）。ドレイン条件は全ジョブが `completed` または `cancelled` になること。
- 依存ジョブが `failed` の場合は削除を実行しない。要求を `blocked` にして理由を残し、ダッシュボードと通知で知らせる。失敗ジョブの再試行成功で `pending` に戻して自動再開する。ユーザーは取消・再試行・強制削除を選べる。
- 手動削除は派生ファイル→元画像→DBの順で実行する。DBは行を削除せず `status='missing'` にしてメタデータを残す。OSゴミ箱から復元して再スキャンすれば再リンクできる。
- 自動置換（`replace`）は元画像だけを削除対象にし、写真は `replaced` のまま表示する。圧縮版は削除しない。
- 圧縮入力は、元画像ファイルが存在する間は原則として元画像（`abs_path`）を使う。表示用の派生を入力にしない。
- 実行中の要求はデーモン起動時に `pending` へ戻す。ファイル手順は冪等で、途中まで移動済みでも欠けたパスをスキップして完了できる。
- 強制削除は `failed` を無視し、`waiting` / `pending` をキャンセルし、`processing` の完了を待つ。処理中の入力を消さない。
- 送信 outbox（#142）は同じ blocker / cancel 経路に追加する。本ADRでは拡張点だけを用意し、outbox テーブルは作らない。

## Consequences

- 自動プロファイルが複数あっても、各ジョブは元画像から圧縮され、元画像の削除は全ジョブ完了後に1回だけ実行される。
- ワーカー数1〜4で最終状態とジョブの成否が一致する。
- 失敗時は元画像が残るため、`replace` で唯一のコピーを失わない。削除は保留され、ユーザーに通知される。
- 手動削除は即座に一覧から消えるが、実ファイルの移動はデーモンが行う。デーモン停止中は要求が残り、起動後に実行される。
- ファイル移動エラーで停止した削除は取消不可（一部がゴミ箱へ移動済みのため）。再試行または強制削除で解消する。
- 写真行とメタデータは残るため、削除後もDBは完全には小さくならない。完全削除は提供しない方針を維持する。
- #142 完了までは送信ジョブのブロック／キャンセルは実装されない。outbox 追加時に `deletion_blockers` と強制削除のキャンセル対象を拡張する。

## Alternatives

- UIが直接ゴミ箱へ移動する: ジョブとの順序を保証できず、途中再起動も復旧できないため不採用。
- 削除時に進行中のジョブをすべてキャンセルする: 圧縮結果を失い、`replace` では元画像だけが残る。ドレイン方針に反するため不採用。
- 失敗ジョブを無視して常に削除する: `replace` で圧縮が失敗している場合、元画像が唯一のコピーになる。データ損失のため不採用（強制削除は明示操作に限定）。
- 写真行もDBから削除する: タグ・メモ・文脈が失われ、ゴミ箱から復元しても再リンクできないため不採用。
- 自動置換でも写真を隠す: 圧縮版は残っており、失敗で保留になると写真が見えないままになるため不採用。

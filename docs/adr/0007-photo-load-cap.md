# ADR-0007: MVPの一覧読み込みを300枚に制限する

- Status: Accepted（将来置換）
- Date: 2026-10-21

## Context

目標は10万枚のライブラリだが、初期実装では一覧・検索が `list_photos(300)` / `search_photos_text(300)` で上限を切っている。UIは `uniform_list` で仮想描画するが、データ取得は全件ではない。10万枚のページングを最初から実装すると、DBクエリ、スクロール位置、検索、サムネイル取得の設計が大きくなる。

## Decision

- MVPでは一覧・検索とも最大300枚を読み込む。
- 仮想リスト自体は実装し、描画負荷は抑える。
- 10万枚対応は別バッチで、キーセットページングまたは全件ID読み込み＋遅延取得のどちらかを選ぶ。
- UIとドキュメントに上限を明記する。

## Consequences

- 初期リリースでは大規模ライブラリの全件閲覧ができない。
- 300枚を超える写真は検索条件を絞る必要がある。
- 将来、`photos` のIDだけを全件読み、表示範囲の詳細を遅延取得する方式に置き換える想定。

## Alternatives

- 全件をメモリに読み込む: 10万件で数十MB。実装は簡単だが、フィルタごとの再読込とサムネイルで重い。
- キーセットページング: 安定したスクロールに向くが、ランダムアクセスと総件数の扱いが複雑。
- SQLite FTS/外部索引: 検索は速いが、一覧のページングは別途必要。
